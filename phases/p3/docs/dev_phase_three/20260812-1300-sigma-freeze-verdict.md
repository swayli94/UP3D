## 2. ★★★ "为什么有极限环":机理钉住了,而且是**定量**对上的

**判定集合是一个硬开关。** `shock_factor_sweep`:

    if m2e >= 1.0: continue      # 自己还超声速 -> 不收费
    if m2u <= 1.0: continue      # 供体亚声速  -> 不收费
    s = σ_RH(sqrt(m2u))          # 一旦两条都过 -> σ 从 1.0 **直接跳到** σ_RH

⇒ 一个坐在声速线上的单元,**φ 的无穷小变化**就能让它进出集合,而它的 σ **跳一个有限量**
`1 − σ_RH(M1)`。把实测被钉住的 Δσ 反解:

| 实测钉住的 Δσ | 反解出的 M₁ | 对照该腿的 m1_max |
|---|---|---|
| **1.55e-02**(comment 腿) | **1.268** | 场里确有这个量级的单元 |
| **1.02e-02**(混合腿) | **1.228** | 同上 |

⇒ **被钉住的 Δσ 就是"一个单元一次开/关"的跳变量**,量级完全对上。
**机理:离散的集合成员 × 连续的场,中间没有任何阻尼 ⇒ 极限环;
周期 = 场把那个单元推回声速线另一侧需要几步(实测 2–5)。**

### 2b. ★★ 而同一个内核家族里,**这个问题已经被解决过一次了**

人工密度的开关是**连续斜坡**(`kernels/upwind.py`):

    nu_e = C * max(0.0, 1.0 - mc2 / max(m2, mc2))     # 从 M = m_crit 起平滑升起,**无跳变**

**密度开关是软的;熵修正的集合判定是硬的。** 而**出极限环的正是那个硬的**。
⇒ 这是一处**内部不一致**,与 B20 当年据以行动的那条("一个方程,两个速度场")同族。
★★ 它给出一个**比松弛/平均更对症的候选**:**把集合判定做成软的** ——
在声速线附近的窄带内让 σ 从 1 连续过渡到 σ_RH,**从源头去掉那个跳变**,
而不是去阻尼它的后果。这条**不在注册的候选清单里**,它是 Part 1 长出来的
(注册明写"Part 3 的方向由 Part 1 决定",所以它在设计之内;**但它是新增的,如实标注**)。
