# 20260822-0800 — **第四轮 附录 #1**：`n*` 的定法改掉 —— 「最紧带」是错的仪器

**性质**：预注册附录。**在跑任何套件之前提交**。

---

## 1. 原计划 §2 站不住

预注册 §2 写：**"低于任何现有锁加在湍流侧量上的最紧带"**，并说本轮**先量出那个带**。
量了：`tests/test_v1_closures.py` / `test_v1_ibl3.py` 里最紧的是 **`1e-12` ~ `1e-14`**。

★★ **但那些多半是自洽/往返检查** —— 例如 Spalding 的 `y⁺ → u⁺ → y⁺ < 1e-10`
（第三轮已核）**根本不经过求积**。**拿一个不受求积影响的带去定求积的点数，就是第 5 问**
（我比的两个数不是同一件东西）。

★ 若照原计划走，我会得出"没有 `n ≤ 96` 够用"，**而理由是错的**。

## 2. 改用**可直接测**的定义

> ★★★ **`n*` = 使得再提高到 `n = 96` 时，**没有任何已提交断言移动** 的最小 `n`。**

★ 它**不需要**我判断哪条带"算不算数"，**也不需要挑任何阈值** ——
**由套件自己回答"哪些已提交的数会动"**，而那正是 F1 最后实际用的判据。

★★ **反向结果**：若 **`n = 96` 本身仍让断言移动**（相对 24），
则报**移动清单**并判 **W-UNDEF**，同时登记 §4 那条更重要的可能：
**高斯不是近壁层的正确工具**（需分层/自适应求积，而不是更多点）。

## 3. 执行顺序（★ 便宜的先跑）

1. **`n = 96` 跑全套件** —— 若**零红**，说明**所有已提交断言的带都宽于 24→96 的移动**
   ⇒ ★★ 那本身就是 **F5 的又一次证实**（锁看不见这类改动），且 `n*` 的问题变成
   **"没有任何已提交的数能约束它"**；
2. 若 **有红**，再跑 `n = 64`、`n = 40` 收敛到最小的 `n*`。

★ **先跑 96 是因为它是最强的一击**：96 若都不动，更小的 `n` 更不会动。

## 4. 追加事前预测

4. ★★★ **`n = 96` 全套件零红** —— 依据：第三轮实测 24→96 的移动最大 **5.2e-03**，
   而 F1 已经证明 **Track V 的锁带宽于 6.5e-04**；5.2e-03 只比它大一个数量级，
   ★ 但**红不红取决于那条带具体压在哪个量上**，所以**这条可以落空**。
5. ★ 若 4 命中 ⇒ **本轮的结论不是"改成 n*"，而是"已提交的数约束不了这个选择"** ——
   那时**改点数就是纯粹的精度决定**，应当**明说没有测试在支持它**。
