## 2. 两处需要事前定死的选择

### 2.1 F1：新增键还是让 bench 显式失败？

**选：在 `newton.py` 里补上这三个键。** 理由写在前面：

- 审计已经证明这三个字段**只存在过于被删除的路线**，而保形路径**信息是齐的**
  （`level_results` 里每级都有 `m` 与 `converged`）⇒ 这是**补一个从来没被 backport 的字段**，
  不是新功能。纪律 #9（两条路径 ⇒ backport 检查）的一个迟到的执行。
- 只让 bench 显式 raise，会把三个脚本**从"静默错"变成"不能跑"**，而其中一个
  （`run_capability_matrix.py`）是**能力边界 §1 M5 引用的那张表的生产者**。

★ **但语义必须复刻，不得自创**（G-S）。已删代码的语义（`d224223:newton_ls.py:1186-1193`）：

```
out["target_reached"]     = target_reached
out["m_last_converged"]   = float(levels[i - 1]) if last_good is not None else None
out["m_final"]            = float(levels[min(i, len(levels) - 1)])   # 返回态真正所在的马赫
```

★ **一处已知的、必须记录的差异**：保形爬坡会**向 `levels` 里插入重试级**
（`newton.py:1710-1713`），所以 `levels[i-1]` 这个下标在保形路径上**语义不同**。
⇒ 本轮**改用 `level_results` 派生**（CLAUDE.md 自己的建议：「the per-level `converged`
flags live in `level_results`」），并在轮次判定里**明写这是与原实现的差异**。

### 2.2 F2：删掉 `sigma_soft_eps/q`，还是给它登记删除条件？

★★★ **事前决定：登记删除条件，不删。理由必须写在看到成本之前：**

审计原文给了两个选项，而**再读一遍两轮的判定**，删除是**错的**：

- 软集合那轮的判定原文是「**机理靶子是对的，但这一版参数化不可采纳**」，
  **kill 四条都不成立 ⇒ 这条路没有被判死**；
- 而审计自己的 §6.2 把「把集合判定做软」列为 σ 冻结那条机理**唯一明确的候选靶子**
  （硬开关 vs 人工密度的软斜坡 = 内核里的一处不一致）。

⇒ 与 `capture_select` **不同类**：那条路线**被 K3 判死**了，所以旗标随路线走。
这一条**没死**，所以原则 4 生效的是它的**前半句**（「必须写下它的删除条件」）
而不是后半句。**本轮补的正是那句从来没写的话。**

**登记的删除条件（写进常数旁边，与旋钮同生共死）**：

> `sigma_soft_eps` / `sigma_soft_q` 在下列**任一**条件成立时删除：
> ① 某个 `(eps, q)` 被采纳为默认；或
> ② 一轮**事前登记**的判定同时给出 **F5 类判据 FAIL**（答案被推出 M1 参考带）
>    **与** eps 敏感性仍非单调 ⇒ 该参数化**路线判死**，旗标随路线走；或
> ③ **2026-12-31 之前**没有任何一轮使用它 ⇒ 按"不活跃"删除。
> 三条都不成立时，它保留为**研究旋钮**，且**每次阶段收口必须复读本条**。

★ **反向结果落在哪（第 1 问）**：若使用者认为该路线其实该判死，那 F2 的正确处置就翻回
"删除" —— 所以本条**明确标为可被一句话推翻的建议**，并在判定里单列。

## 3. Kill criterion（**写在开工之前**）

GS4.0 在下列任一条件成立时**停下并如实报 FAIL**，不扩大范围、不改判据：

1. ★ **G-B 对不平** —— 改动前后套件数字差异无法**逐条点名**解释 ⇒ 停，回滚到能对平为止。
   （level-set 删除那次的账正是这样对平的，标准不降。）
2. ★ **G-N 有任何一个已提交数字移动** ⇒ 停。GS4.0 **无权**移动任何解。
3. ★ **F6 的 manifest 需要改动 `.msh` 的字节，或需要改动 10 个生成器以上的内部逻辑**
   ⇒ 停，降级为「只提供 `mesh_fingerprint` 供**消费侧**按需调用」并记 RECORDED。
4. ★ **总机时超过 30 min** ⇒ 停。GS4.0 按设计**几乎不需要求解**；超了就说明我把它做成了
   另一件事。（唯一的大宗是收口的快层 ~9 min + 全套件 ~8 min。）
5. ★ **任何一条修复需要一个新的裁决**（例如"该不该删 `post/unified.py`"）
   ⇒ **不自行裁决**，记 RECORDED 并留给使用者。
