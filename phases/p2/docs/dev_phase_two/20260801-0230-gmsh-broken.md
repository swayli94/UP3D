# 环境发现:**这台机器上的网格生成是坏的** —— `import gmsh` 直接失败

轮次文件名:`20260801-0230-gmsh-broken.md`
分支:`claude/phase-two-s2`
发现时机:GS2.1 第一步要生成 LE 加密网格时(预登记 `20260801-0200`)

---

## 1. 症状

```
$ python -c "import gmsh"
OSError: libGLU.so.1: cannot open shared object file: No such file or directory
  (/home/lrz/.local/lib/python3.11/site-packages/gmsh.py:92, CDLL(libpath))
```

**`import gmsh` 本身就失败** —— 不是我的调用方式问题:四条腿的网格生成全部以同一条
`libGLU.so.1` 报错终止(如实记为 MISSING,按预登记 §3 不用相邻腿顶替)。

## 2. 为什么这是一条**项目级**发现,不只是我的挡路石

仓库把"重新生成网格"当作**常规工作流**:
* CLAUDE.md 工作流 / 纪律 #7:M6 的 `.msh` 是 gitignored,"regenerate ~30 s via
  `cases/meshes/onera_m6/generate_onera_m6.py`";
* 16 个 M1 测试、以及 M3/M4 无尾迹族的测试,**都以"网格缺失就 skip"** 的形式依赖它;
* 使用者本人在审计任务里写的就是"**如果有数据或网格缺失就重新生成**"。

**在当前环境下,这条路是断的。** 磁盘上现存的 `onera_m6/{coarse,medium}.msh`
是更早某个时刻(或别处)生成的 —— 也就是说**现在没人能复现它们**,
而这正是仓库自己"证据必须可再生"纪律的反面。

## 3. 缺什么(实测的完整依赖链)

pypi 的 gmsh wheel(4.15.2)链接了 GUI/OpenGL:逐个补齐后测得的**完整**缺失集是

| 库 | 提供者(Ubuntu jammy) |
|---|---|
| `libGLU.so.1` | `libglu1-mesa` (9.0.2-1) |
| `libOpenGL.so.0` | `libopengl0` |
| `libGLdispatch.so.0` | `libglvnd0` |
| `libGLX.so.0` | `libglx0` |

## 4. 本轮采用的**不动系统**的绕行(可逆)

不需要 sudo:把四个 .deb 下载后 `dpkg -x` 解到一个本地目录,再用 `LD_LIBRARY_PATH` 指过去。

```
mkdir -p <dir> && cd <dir>
for p in libglu1-mesa libopengl0 libglvnd0 libglx0; do apt-get download $p; done
for d in *.deb; do dpkg -x "$d" .; done
export LD_LIBRARY_PATH=<dir>/usr/lib/x86_64-linux-gnu
python -c "import gmsh; gmsh.initialize(); print(gmsh.option.getString('General.Version'))"
# -> 4.15.2 OK
```

⚠ 本轮把它解在**会话 scratchpad** 里,所以**这个修复不持久** ——
下个会话会再次撞上同一条报错。

## 5. 建议(需要使用者裁决,因为它动系统)

**持久修法(推荐)**:`sudo apt install libglu1-mesa libopengl0 libglvnd0 libglx0`
—— 4 个小包、标准依赖、可逆。**我没有自行执行**:它改的是机器而不是仓库。

**备选**(都不用 sudo,但各有代价):把 §4 的目录解到一个**持久**位置并写进
环境配置;或换一个不链 GUI 的 gmsh 构建(pypi 的 wheel 都带 FLTK/OpenGL,
需要自建或换 conda 源)。

## 6. 建议顺带加的守卫

现在"gmsh 坏了"的表现形式是**一堆 skip**(测试)或**一条 OSError**(脚本)——
两者都容易被读成"没事"。建议加一个**显式的环境自检**:
`pytest` 会话开始时(或一个 `tests/test_env_meshgen.py`)尝试 `import gmsh` +
`gmsh.initialize()`,失败则给出**指名道姓的 skip 原因**(缺哪个库、装什么包),
而不是让 16 个 M1 测试静默 skip。**本轮不实施**(它改测试收集行为,应当单独一轮)。
