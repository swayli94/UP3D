## 3. 事前登记的判据

**(P1 载重)** 该腿必须**收敛到目标马赫**(整条 ramp `converged=True`)。
不收敛 ⇒ 该腿失败,**不得**用"少几秒"抵消。

**(P2 时间)** 整条 ramp 墙钟必须**低于 S-base**。
⚠ 陷阱:更差的种子会让 level 0 多花 Newton 步,**省下的种子时间可能被吐回去**。
所以判据是**整条 ramp 的墙钟**,不是种子那一项。

**(P3 不变性)** 与 S-base 的解比:`cl_p` / `cl_KJ` 相对差。
★ 这一条与 GS3.1 的处置**不同**,理由要事前写明:预条件子改动**不应**改变答案,
而**种子是合法的算法选择**(P14 就把 pressure Newton 的种子换成 probe 解)。
本项目已实测出**解在 1e-4 上不唯一**(冻结选择随迭代路径变)。
所以这里 **P3 = RECORDED,不作否决**:
* 差 **≤ 1e-8** ⇒ 同一个根,干净;
* **1e-8 ~ 1e-4** ⇒ 落在已确立的冻结非唯一性带内,**记录并交使用者裁决**
  (与 `M_max` 那次同样的处置);
* **> 1e-4** ⇒ 超出已知带,**视为该腿失败**(那不是非唯一性,是种子把解带到别处)。

**(P4 必须记录)** 每腿的 level-0 Newton 步数、GMRES 总数、各层墙钟 ——
用来分辨"种子省了时间"与"种子把成本转嫁给了 Newton"。

## 4. 晋升规则(事前定,防止事后找理由)

**同时满足 P1 与 P2、且 P3 ≤ 1e-4** 才提名采纳;
**P3 > 1e-8 时不自行采纳**,连同数字交使用者。
若最好的腿只省下 < 3 s(即 < 6 % 墙钟),**记为不值得**,不改配方 ——
种子路径的改动会波及每一个调用点,不该为 6 % 付这个代价。

## 5. 边界

只改 `phi_init` / `n_picard_seed` 的**传参**,**不动库代码**。
若某腿胜出,采纳仍是**另一个动作**(要改 `NEWTON_M6_RECIPE` 并跑全套 + 门控)。
