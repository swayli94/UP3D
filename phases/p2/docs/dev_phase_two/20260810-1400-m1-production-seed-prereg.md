**执行前提交。** 填的是能力边界 [§3.6](PHASE_TWO_CAPABILITY_BOUNDARY.md) 记下的那个洞。
**判据不是本轮新定的** —— 就是 roadmap §2 的 M1 三条,一字未动;

## 1. 为什么需要复测

现有的 M1 读数(2026-08-05)是 **`n_picard_seed = 5`**,而**生产默认是 seed = 0**。
当天 seed = 0 的 medium **不收敛**(撞 `m_cap`,7265 lim / 758 flr),所以 (b)(c) 在 medium 上
**无法评估**。
之后落地的 **`clamped` 触发的自动种子回退**把这个案例救回来了(M1a 重定时实测 M0.80 三级
全部收敛、0 clamp)—— 但 **M1 自己的三条判据从未在这条路径上跑过**。

## 2. 设计(全部沿用现有脚本,不改判据)

`bench/run_m1_gate.py`,`--density default`(库默认 = 熵修正 ON)。
它的 seed 轴本来就是 `(0, 5)`,所以**一次运行同时给出生产默认与 like-for-like 的对照**。
工况 NACA0012 **M0.80 / α1.25**,两级 `(coarse, medium)`,`upwind_c ∈ {1.0, 1.5, 3.0}`。

**本轮对脚本的唯一改动是仪表,不是判据**:
1. ★ **记录 `seed_fallback`** 的 `fired` / `seed` 到每一行 —— 否则一条 seed = 0 却收敛的腿会被
   **静默归因成"seed 0 现在行了"**,而实际做功的是回退。这正是本项目反复付过代价的那类归因错。
2. ★ **钉线程帽**(今天刚测到的教训:同一次求解未钉帽 566.6 s / 钉帽 113.7 s),并记录帽值。

## 3. ★★ 事前钉住的两个解读规则

| | 规则 |
|---|---|
| **R1 回退腿算不算读数** | **算。** 回退是**生产路径的一部分**(库默认行为),所以被它救回来的腿是生产默认的真实读数。**但必须在结论里写明该腿 `fallback_fired = True`** —— 不得表述为"seed 0 收敛了"。 |
| **R2 线程依赖的失败怎么读** | 若 medium 的 seed = 0 腿在本次(8 线程)失败,而这正是**已登记的线程依赖**(边界 §4.3:8 线程失败 / 16 线程通过),则它**不是** M1 的新负结果,**必须**报为"该腿在本线程数下不可读",并在 16 线程上复跑一次再下结论。**不得**把一次线程依赖的失败写成"M1 (a) 在生产默认上不成立"。 |

★ 另:按 GS1.4,**带 clamp 的状态不是解** —— 任何 `n_limited > 0` 或 `n_floored > 0` 的腿
其 `x_shock` / `cl` **都不是读数**,无论 `converged` 报什么。

## 4. 事前判据(= roadmap §2 的 M1,未改)

| | 要求 |
|---|---|

**预期(写下来以便被否)**:(a) 大概率两级都在带内(seed = 5 上已是 0.6073 / 0.6006);
(b)(c) 大概率仍 FAIL(seed = 5 上是 −16.2% 与 9.4% / 17.9%)。
⇒ **本轮最可能的产出不是"M1 达标",而是把 M1 的 FAIL 从"seed = 5 的读数"升级为"生产默认的读数"**。
这本身就是边界文件需要的东西。
