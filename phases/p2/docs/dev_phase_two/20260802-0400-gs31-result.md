## 1. `direct` 到底是什么(读代码,纠正一个常见误解)

它**不是**每步精确直接解:

* **第 0 步**:`spla.splu(J_ff)`(SuperLU 精确稀疏 LU)+ 对 Kutta 秩-n_st 耦合的**精确 Woodbury**
  修正;代码记 `eta = 0.0`;
* **第 1 步起**(生产配方 `direct_refactor_every = 1000` ≫ 14 步):
  **陈旧 LU 作预条件的 GMRES,`rtol = direct_reuse_rtol = 1e-8`**;GMRES 失败才回退重分解。

⇒ 三个配置是一条**线性容差阶梯**:`amg` loose **1e-2** → `direct` **1e-8** → `amg_tight` **1e-10**。

**"收敛"的保证不来自线性解法,来自非线性残差**:\|R\|_∞ = **6.04e-15**(T0)、Kutta \|F\| = 2.08e-16。
⚠ 边界:该残差是在**冻结后的系统**上测的,所以 `direct` 给的是"**某一个**冻结系统的精确根";
它**逐位可复现**(对照已测),但那是确定性,不是唯一性。

## 2. 差别的机制:**冻结了不同的选择**(纠正我自己的过度断言)

我先前说"那个差**就是**线性解不精确,不是冻结分叉"——**说过头了**:收紧 EW 会同时让
迭代路径与冻结选择对齐,那个实验**分不开**两种机制。直接比较捕获的数组:

```
direct: 3 次冻结捕获, |R| 6.36e-15
amg   : 3 次冻结捕获, |R| 1.02e-14
  upstream 差 8/145303 (0.0055 %) · branch 差 6/145303 (0.0041 %)
```

⇒ **两条路冻结的是不同的系统**,各自**精确**收敛到**自己那个**系统的根
(所以两边 \|R\| 都是 1e-14),两个根差 1e-4。
**这个离散解在 1e-4 上本来就不唯一**,预条件子只是"采样到哪个根"的一个途径 ——
而项目已记录过另一个采样器:**GV5.1c 在 8 线程下落到"第 4 个不动点"**。
⇒ 若这 1e-4 对产品重要,该修的是**冻结机制**(B15/B21 的 churn),**不是**预条件子。

|---|---|---|---|---|---|---|---|

`*` 取自已提交 `tip_allscales.csv`(纪律 #2:不重付 66 min)。

脚本据此打印的"冻结分叉、1e-8 不可达"是**我的取整造成的假象,作废**。
可读的部分:`amg_tight` 的 le_upper **0.1757553** 与 direct 存储的 **0.175755** 全同,
而 loose 的 **0.1757786** 不同。**教训:from_prior 行必须存全精度,否则它会污染判读。**

## 4. 结论:**张力只在小网格**

`amg_tight` 在 **1.16 M** 上 **3.96×(过 ≥3× 杠)且复现 direct**。
我先前报的"两条判据互相拉扯"是 **Tp5/T0 尺度上的现象**,在生产规模上**自己消解了**。
⇒ 采纳配置的选择因此从"精度 vs 速度"变成"**要不要为多出的 2× 付一条双路径规则**"。

## 6. 顺带的勘误(roadmap GS3.1 原文)

"只把 `precond` 换成 `amg`……**答案一个数字都没变**" —— 那是审计在 **6 位**上、
且在 **loose EW(1e-2)** 下比的。实测该设置把答案动 **1.33e-04 ~ 2.71e-04**;
要真正不变需收紧到 1e-10。**"白送项"是真的,但比宣传的小,而且大网格上才划算。**
