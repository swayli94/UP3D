## 1. GS3.3 与一条**已关闭的门**冲突

roadmap GS3.3:"**去掉马赫爬坡**:目标马赫直接伪时间 + 非精确 Newton,种子改便宜的线性化解",
验收 = 种子+爬坡开销 **13.6 s(占 43%)→ < 3 s**;同解。

而 **G10.3 `no-ramp direct-solve feasibility`,CLOSED 2026-07-11,判决 KEEP the Mach ramp**
(8 次运行 + 提交的 CSV,事前登记了 (A)/(B)/(C) 三类与晋升规则):
* 远离 fold(M6):no-ramp **收敛到同一个解**(class A),分支选择**不是**那里的约束;
  但 Picard-5 经过 **clamped** 状态(medium 峰值 45 lim+flr),141.4 → 79.0 s(**快 44%**)违反
  clamp-free 条款;Picard-40 只快 6.6%,违反 ≥20% ⇒ **无路径满足规则**;
* fold 区(NACA medium):两种种子**都是 class (C)**;深种子无爬坡时**主动有害**。

⇒ 纪律 #8:**不得在无新证据时重开已关闭的负结果**。
但**确实有新证据**:G10.3 是在 `precond="direct"` + 滞后 LU 下测的,
而爬坡的主要开销正是"**每层一次 splu + 种子**",**GS3.1 刚把它换成 AMG**。
所以本轮不是"重开",是**在新成本基准上复核**。

## 2. 复核结果:**新证据不但没推翻 G10.3,反而加强了它**

M6 medium M0.84,今天的配方(amg + EW 1e-10):

| | 墙钟 | 收敛 | seed | linsolve | cl_p |
|---|---|---|---|---|---|
| **爬坡**(0.70/0.75/0.80/0.84,步 2/2/3/14) | **70.8 s** | ✓ | **0.00 s** | 40.6 s (57%) | 0.263888 |
| **无爬坡**(M0.84 直解,Picard-5) | **222.8 s** | **✗** \|R\| 2.29e-05 撞 60 步 | **15.4 s** | 186.8 s | 0.263891 |

**无爬坡今天慢 3.1× 且不收敛。** 而 G10.3 当年测到它**快 44%** ——
**关系翻转了**,因为爬坡的开销本来就是每层的 splu,**AMG 把它消掉了**。

## 3. ★ 另一半也被证伪:**生产爬坡路径的种子开销是 0.00 s**

审计的 "13.6 s 种子 = 43%" 是**单次直解**的数字 —— 本轮在无爬坡腿上测到 **15.4 s**,**吻合**。
但 `solve_newton_transonic` 各层用**上一层热启动**,聚合 `timings["seed"] = 0.00 s`。

⇒ **GS3.3 的动机所依据的那笔开销,生产路径根本不付。**
"把种子改成便宜的线性化解"**没有东西可省**。

## 4. 结论:GS3.3 **前提证伪,建议关闭**

* "去掉爬坡" = G10.3 的**已关闭负结果**,在新成本基准上复核后**更负**(3.1× 慢 + 不收敛);
* "改种子" = 生产路径**种子成本为零**,无可省;
* **GS3.1 已经交付了 GS3.3 的意图**:它要省的正是每层 splu,而 AMG 把 M6 medium 的
  爬坡从(G10.3 记录的)141.4 s 压到 **70.8 s**。

★ **建议把 GS3.3 关闭为"前提被 GS3.1 消解"**,而不是留着当一个待办 ——
留着它会让后人以为还有 13.6 s 可捡。

## ★★ ERRATUM(2026-08-02,同日,由 GS3.4 的时间账目发现)

**§3 与 §4 里"生产爬坡路径的种子开销是 0.00 s"是错的。真实值是 14.44 s = 墙钟的 28.3 %。**

**错在哪**:我读的是 `result["timings"]` —— 而那是 `solve_newton_transonic` 的
**最后一层(0.84)**的计时,那一层确实 seed = 0(它从 0.80 热启动)。
**整条 ramp 的和在 `timings_total` 里。**
而这正是代码自己 docstring 里写明的陷阱:

> `sum_timings`: "The ramp wrappers report this as **`timings_total`**, alongside the
> **final-level** `timings` they have always returned — reading the latter as if it
> were the whole ramp is the **'timings dict = final level only' footgun (P8 record)**."

**我一头撞了进去** —— 而且这不是个隐蔽的坑,它有名字、有前例记录。

**真实预算**(M6 medium M0.84,墙钟 50.94 s,`timings_total`):

| 阶段 | 秒 | 占比 |
|---|---|---|
| **seed(Picard)** | **14.44** | **28.3 %** |
| **linsolve** | **29.40** | **57.7 %** |
| precond | 2.25 | 4.4 % |
| assembly | 1.91 | 3.8 % |
| residual | 0.93 | 1.8 % |
| 合计 | 49.30 | 96.8 % |

**发现路径**(记录下来,因为它说明为什么"先把账做平"值得做):
层 0.70 与层 0.75 都是 2 步、GMRES 81 vs 87、各阶段合计 1.73 vs 1.80 s,
**墙钟却是 17.69 vs 1.90 s** —— 15.97 s 无处归属。
先猜 JIT 编译(**同进程连跑两次证伪**:两次都 ~17.6 s),
再猜冷启动的 forcing(**放松 eta0 只省 0.7 s,且直接打破不变性 1.41e-05,证伪**),
最后 cProfile 指到 `picard.py:421 solve_subsonic_lifting = 14.78 s`。

## 修正后的结论

| GS3.3 的两半 | 状态 |
|---|---|
| **"去掉马赫爬坡"** | **仍然证伪**(G10.3 的已关闭负结果;新成本基准上更负:无爬坡 222.8 s 不收敛 vs 爬坡 70.8 s 收敛) |
| **"种子改便宜的线性化解"** | **★ 未被证伪 —— 14.44 s / 28.3 % 是真的,而且还在** |

⇒ **GS3.3 不应整体关闭。** 建议:**"去爬坡"关闭为负结果**,
**"换种子"作为独立门保留并开工** —— 它是 GS3.4 预算里第二大的一项,
而且与"去爬坡"无关(换种子**不需要**去掉爬坡)。

★ 附带的教训(与本会话已记的同类):**一个未归属的时间块不要猜三次,profile 一次。**
我猜了两次(JIT、forcing),两次都被自己的对照证伪,才去 profile —— profile 从一开始就该做。
