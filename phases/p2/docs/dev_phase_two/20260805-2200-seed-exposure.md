# 20260805-2200 — `n_picard_seed = 0` 到底在哪些情形失败,以及为什么

用户 2026-08-05 直接问的两个问题。假设**执行前写进脚本 docstring**
(`bench/run_seed_exposure.py`),并且它不是我想出来的 —— 它来自项目自己的记录。

## 0. 一句话

**不是"种子"失败,而是"无种子 **且** 直接在超临界目标马赫上冷启动"失败。**
预写的预测 **P2 成立**:同一算例加上马赫爬坡(第一层 M0.70 亚临界)后,seed 0 **收敛**。
而 GS3.3b 的注释**早就写下了这个安全条件**,只是**没有被带到调用点**。
失败的机理**不在前缘**:限幅单元 **81% 在 MID / 17% 在 TE / 0% 在 LE**,峰值在 **x = 0.75**,
而且**第 3 步就开始**限幅 —— 是冷启动在超声速区里过冲,不是迭代走偏。

## 2. 为什么(机理)

三条证据合起来只支持一个读法:

1. **位置**:限幅**全在激波及其下游**(MID 81% + TE 17%),**前缘 0%** ⇒ 不是 LE 吸力峰,
   是**超声速区**。
2. **时机**:**第 3 步**就限幅,而不是几十步后走偏 ⇒ 是**初始场**的问题,不是迭代的问题。
   对照:两条收敛腿也**短暂**限幅过(第 49 步 / 第 19 步)然后恢复 —— 所以
   **"限幅过"不是失败标志,"第 3 步就限幅且再也回不来"才是**。
3. **爬坡救得回来**:同样 seed 0,只要第一层是**亚临界的 M0.70**,就 0/0 收敛到 4.49e-11。

⇒ **机理**:Picard 种子的作用是给 Newton 一个**已经带着超声速区形状**的起始场。
没有它、又直接在 M0.80 冷启动时,前几步在超声速区里**过冲**;人工密度/迎风开关随即
作用在这些过冲速度上,单元冲过 `m_cap`,限幅器钳住 7265 个,而按 GS1.4 契约
**带限幅的状态不得上报为收敛**。加上爬坡后,**上一个马赫级的收敛解接替了种子的角色** ——
所以爬坡与种子是**同一个功能的两种实现**,只要有一个在就够。

## 3. 那么"哪些会失败"

**失败条件是三者的合取**,不是单一条件:

| | 条件 | 证据 |
|---|---|---|
| (a) | **不传种子**(继承 08-02 的默认 0) | seed 5 同配方收敛 |
| (b) | **直接在超临界 M∞ 上求解**(没有爬坡、没有热启动) | 加爬坡即收敛 |
| (c) | **网格细到能解出那个超声速区** | 同工况 **coarse 活、medium 死**(coarse M_max 1.394、0 限幅) |

★ **(c) 是反直觉的一条**:**加密使它变坏**。coarse 之所以活下来,是因为它**解不出**
那个足以触帽的峰值 —— 这与 M1a 的 fine 腿(唯一被 seed 移动的一层,§4)是同一方向。

**静态数不出暴露面,如实说**:103 个 `solve_newton_lifting` 调用块里有 **24 个显式传了种子**
(对默认改动免疫),其余继承;但**是否暴露取决于该调用点的 M∞ 与网格**,而马赫大多来自
模块常量,`grep` 读不到 ⇒ **我不给"暴露 N 个调用点"这种数**(第一版脚本给出的 68 是解析假影)。

**测出来的暴露面**(即在测试与门控集里真的被打到的):
- `tests/test_p4_transonic::test_g41_transonic_medium_gate`(M0.80 medium,门控 + **非严格 xfail** ⇒ 看不见);
- `tests/test_s1_m1a_envelope::test_m1a_medium_to_fine_convergence` 的 **fine** 腿
  —— **不是失败**,是**答案位移**(cl 0.254830 → 0.252930,d2 变号);
- `bench/run_m1_gate.py`(M1 的判定脚本本身)。
- **全套 ungated 694 passed 不受影响** ⇒ 未被测试覆盖的调用点是**未知项**,不是"已确认安全"。

## 4. 两级暴露,不要混为一谈

| 级别 | 表现 | 例 |
|---|---|---|
| **硬失败** | 撞 `m_cap`、拒绝上报收敛 | M0.80 medium 无爬坡 |
| **软位移** | 收敛、0 限幅,但**落到另一个解上** | M1a 的 fine 腿(−0.75%,d2 变号) |

软位移这一级更难发现,因为它**不报任何错**。它与 GS3.3b 自己记的
"答案位移 2.94e-05 relative … that is the freeze non-uniqueness this phase measured"
是同一现象,只是在 fine 上放大到 **−0.75%** 并**改变了一个判据的符号**。

## 5. 对使用者三个选项的影响(§ 20260805-1200 §5)

本轮把选项 (ii) 从"建议"变成**有具体触发条件的建议**:

- **触发条件可以写死而且是可测的**:`clamped`(GS1.4 已有的标志)为真 ⇒ 用种子重试一次。
  不需要新阈值,也不需要判断"是否超临界"。
- **成本有界**:只在**已经失败**的解上多付一次种子(M0.80 medium 是 19 s),
  成功路径**一分钱不花** ⇒ 保住 08-02 想要的简洁与 25% 提速。
- ★ **但它治不了软位移**(§4):M1a 的 fine 腿是**收敛且 0 限幅**的,触发条件不会开火。
  软位移需要的是**答案锚点**(M1a 那条测试就是),不是回退机制 —— 两件事分开处置。
