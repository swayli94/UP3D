⇒ 这不是一次性抖动,是可复现的能力事实。

## 4. ★ 为什么不能用 G8.2 那个修法(加 taper)

G8.2 的 round-tip 失败被"加生产 taper"解决了(M0.84、\|R\| 6.155e-15、0/0)。
**b22 不行,而且理由是结构性的**:实测 `solve_multivalued_newton_transonic` 的签名里
**根本没有 `tip_taper`**(也没有任何 tip/taper/fringe 参数)。taper 缩放的是**conforming 路径的
Kutta 行**,而 B31 已把 **LS 侧的 C 类翼尖治法测为负结果**(C1 内侧回流 −19.5% / C3 coarse 发散),
`outboard_fringe` 保留为默认惰性。

⇒ **圆角翼尖对 LS 路径的代价是赎不回来的。** 这是两条路径**能力分叉**的一个新实例。

## 7. 本轮我的错误

- ★ **缓存不够 ≠ 没缓存**(第五次相关教训):第一次测量存了 φ/γ/残差/M_max,**没存
  `level_results`** —— 而重锚需要的正是**逐级 clamp 数**。多付了一次 37 分钟的重测。
  "缓存"这条纪律得写成"**缓存到足以支撑你要下的那个结论**",不是"存几个明显的字段"。
- **两条路径的键名不同**:`level_results` 里 conforming 用 `m`、level-set 用 `m_inf`。
  按 `m` 读直接 `KeyError`,而且是在**求解之后**的报告代码里 —— 又一次"报告代码没被守卫"。
- **嵌套引号的 f-string 在 3.11 不解析**,本阶段第二次。
- ★★ **用手工 `cp` 交换 git 已跟踪的库文件,把工作区搞坏了。** 两层同时失效:`$SC` 在
  heredoc 脚本内**从未定义**(它是外层 shell 的变量,而 heredoc 用了引号形式)⇒ 备份 `cp`
  写到 `/_n.py` 权限拒绝;而那个脚本**没有 `set -e`**,于是继续执行、把两个库文件覆盖成旧版,
  恢复的 `cp` 也失败。工作区带着**缺 190 行已提交工作**的库停在那里,直到
  `git checkout -- pyfp3d/` 修好。**零损失,因为改动已提交** —— 而这正是要点:
  **文件在 git 里,git 就是备份**,该用 `git checkout <rev> -- <paths>` 而不是 `cp`。
  ★ 本会话**早先几次 A/B 用的正是 `git stash`**,这次却退回到手工 `cp`。
  已写进 [CLAUDE.md](../../../../CLAUDE.md),并在重跑脚本里加了 `set -euo pipefail` + `trap restore EXIT`。
