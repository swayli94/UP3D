## 1. 修了什么

`xblsys.f:856-877`（`BLVAR`，`ITYP=2` = **湍流壁面**）：`CτEQ ∝ HKB · HKC²`，
其中 `HKB = Hk−1`、`HKC = Hk−1−18/Re_θ`（下限 0.01）—— **两个不同的量**。
第五轮写成 `(Hk−1)³`，并把 `GCCON` 注为「wake only; unused here」。
源码自己写着 `ITYP = 1 : laminar / ITYP = 2 : turbulent`（`:794-795`），
`xbl.f:810` 转捩后调 `BLVAR(2)` ⇒ **该修正正用在这里**。

★ **第五轮的 G-SOURCE 打印了 `GCCON = 18.0` 却没发现它没被用** ⇒
**守卫覆盖的是"常数值对不对"，不是"常数用没用对地方"**。本轮新增 **F-USED** 补上：
把 `GCCON` 置 0，结果必须改变（实测变 4.45 %）。

## 3. ★★ 更有价值的读法：**残差从"来历不明"变成"来历已知"**

修前出带的两处是：**一站低 `Re`** + **一簇中段(来历不明)**。
修后是：**7 站连续位于 `Re_θ 574–858`**，而那正是**转捩后的弛豫段**
（`x_tr = 5.0`，这几站在行进最开头）。

⇒ **误差在数值上更大了，但它现在集中在一个机理已知的位置** ——
即第五轮预注册就登记过的转捩模型（瞬时切换 vs XFOIL 的 e^N 斜坡，GV3.1 实测首站 `c_f` +44 %）。
**中段那个说不清来历的簇消失了。**

★ 机理也说得通：`GCC/Re_θ` 在低 `Re_θ` 最大 ⇒ 修正把 `CτEQ` 压低最多 ⇒ `c_D` 降 ⇒
`H` 在转捩后**回落得更慢**（`H(Re=600)` 1.4919 → 1.5213）⇒ 离参照更远。
**这是"转捩后弛豫更长"，不是"闭包更差"。**

## 4. ★★ 套件锁**没有察觉**这次改动 —— 这是一个覆盖缺口

修后跑既有 48 条锁：**全绿**。原因：每一条湍流锁的窗口都从 **`Re_θ ≥ 800`** 起，
而**改动最大的区间恰恰在它下面**（574–858）。

⇒ **窗口把变化排除在外的锁，对那个变化没有覆盖。** 本轮补两条
（`tests/test_gs41_turbulent_closure.py::TestPostTransitionRelaxation`）：
- `H` 在**固定 `Re_θ`** 上的插值锚（600 / 1000 / 3000）；
- 转捩后 `H` 必须单调回落。

★ **第一版锚也踩了坑**：我锚"`Re_θ<800` 的最大 `H`"，实测 **1.8296** 而脚本里是 **1.5213**
—— 因为两者的**首站与 `x_tr` 的距离不同**，即**两个不同的站点集**（第 5 问）。
改为**插值到固定 `Re_θ`**（实测在 40/60/90 站上稳定到 0.005）后才是良定的。
