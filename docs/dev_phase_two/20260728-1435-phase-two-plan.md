## 1. 目的

把 2026-07-28 全面审计的结论，转成一份**能约束后续每一轮工作的计划**，并且把
第一阶段那些导致工作走偏的机制在制度上堵掉。

这一轮**不改任何代码**，所以没有物理门。它要达到的是三件事：

1. 定义**五条产品指标**（M1–M5），并给每条写下当前实测值——今后每轮都对着它们汇报；
2. 定义**阶段顺序**（S0–S6）和每个阶段的 kill criterion，尤其把
   "跨声速激波算子"设为总闸门；
3. 定义**记录格式**（一轮一文件 + progress.md 一行 + 三种判定），以及一份
   明确的禁止项清单。

**什么算这一轮失败**：如果写出来的计划里出现"以自己的历史数字为验收标准"、
或者允许"解不出来就换工况"、或者没有可执行的验收脚本入口，就是失败——因为那正是
第一阶段的失效模式，换个文件名重演一遍没有意义。

## 3. 怎么测的

这一轮没有数值测量。可核查的是**计划自身的自洽性**：

- 五条指标的"当前值"全部来自审计的实测或已提交证据，且在 roadmap §6 的现状快照里
  给了来源；
- 每条指标都指向一个具体算例 + 参考数据（都已在仓库里：
  `cases/reference_data/naca0012_m080`、`rae2822_experiment`、
  `onera_m6_experiment`、`naca0012_viscous_xfoil`）；
- S1 的验收不依赖任何外部锚点的那一半（"两级网格 cl 差 < 3%"、"C 扫掠 < 3%"）
  是自一致性判据，任何时候都可判定；依赖外部锚点的那一半（激波 0.61±0.02）
  用的是项目已提交的参考 CSV。

**给使用者的两个决策点**（我不自行决定）：

1. **S0.2 的删改范围**：把 bitwise 断言改成公差断言，会让第一阶段的一批
   "bit-identical 锁"失去原意（它们锁的是"某个默认关闭的旋钮不改变结果"）。
   我建议：保留数学恒等式类，其余改成 1e-12 相对公差。要不要更保守？
2. **S6 的战略取向**：如果 S1/S2 都达标就继续非结构路线；若 S2 达不到 2%，
   是上等参 P2，还是转半结构（C-H）贴体网格？这个决定影响 S3 之后的全部工作量，
   建议在 S1 结束时就先做倾向性判断。
