## 3. ★★ 分类器自身的缺陷:一个手定阈值决定了一个已发布的结论

r_c=0.0375 的残差尾部是**周期精确为 3 的极限环**:

```
9.0371e-05 → 8.0590e-05 → 4.0257e-05 → 9.0361e-05 → 8.0592e-05 → 4.0257e-05 → …
差分符号:  - - + - - + - - + - -        同一组三值重现到 4–5 位有效数字
```

两个缺陷:

1. **重现容差 1e-12 太紧** —— 一个极限环在浮点里跑几十步不会重现到 1e-12,所以
   `res_revisits` 数到 **0**;
2. **`descent10 = 2.0021` 只是"周期内高点比低点高 2 倍"** —— 它是**十步窗口落在周期何处**的
   算术产物,与收敛**无关**,而它恰好落在我**手定**的 `>2.0 ⇒ budget_limited` 那一侧。

⇒ **一个我随手定的阈值决定了一个已写进 note 与提交信息的结论。** 这与本阶段 EW forcing、
taper r_c 的教训同形:**任何固定阈值是标定,不是保证。**

**修法不是换一个数**,而是加一个不依赖阈值的必要条件:

- 重现容差 **1e-12 → 1e-4**
- **`budget_limited` 现在要求尾部单调下降** —— 极限环无论 `descent10` 多少都过不了

**在两个有已知答案的案例上验证**(这是修改的验收,不是声明):

| 案例 | 已知答案 | 修后判定 |
|---|---|---|
| r_c=0.0375 | 极限环(加预算逐位不动) | **limit_cycle** ✓ `revisits=12, monotone=False (n_up=3)` |
| LE-1 的 ls_naca_medium | 真预算受限(加预算 6 步收敛) | **budget_limited** ✓ `descent10=1699, monotone=True` |
