# 预登记(GS3.2 前提检验):那 480 次迭代,**真的是拉伸造成的吗?**

轮次文件名:`20260802-0600-gs32-prereg.md`
分支:`claude/phase-two-s2`
**本文件在写任何测量代码之前提交。**

---

## 1. 门与它所依据的归因

roadmap 的 GS3.2:"**真正的二维路径(三角形单元),停止用'一层棱柱切四面体'冒充二维**",
验收 = 二维单点 < 1 s;**AMG 迭代数从 480 降到 < 50**;答案与 2.5-D 一致 < 0.5%。

那个 480 来自审计 §3.2:NACA 2.5-D medium、21 696 DOF、**AMG+CG 480 次 / 1.20 s**
(同表里 M6 coarse/medium/翼身是 13 / 15 / 16 次)。审计的归因是:

> 2.5-D 那张网格是唯一 AMG 表现差的 —— 它是"把二维问题拉伸成一层三维棱柱再切成薄片
> 四面体"的产物,**各向异性极端(边长跨 300:1)**。

## 2. ★ 那个归因有一个可以直接证伪的漏洞

2.5-D 网格的各向异性有**两个来源**:

* **面内**:物面附近 ~0.001 到远场 ~0.3 的加密梯度 —— **真正的二维三角形网格里一模一样存在**;
* **z 向**:一层等厚(0.02)的拉伸 —— **只有 2.5-D 才有**。

**若 480 次主要来自面内梯度,则 GS3.2 建完也不会改善 —— 门白建。**
审计把 300:1 整个记在拉伸头上,但**没有把两个来源分开测**。

## 3. 判别(不需要建二维求解器)

同一张**二维三角剖分**(从 2.5-D 网格的 z=0 对称面直接取出,~20 596 三角形 / ~10 444 节点)上
组装 **P1 三角形刚度阵**,跑**同一个** `build_amg_preconditioner` + CG 到 rtol 1e-8,数迭代。
两边都用纯 Laplace(ρ≡1)+ 远场 Dirichlet,**只让维度不同**。

| 事前预测 | 结论 |
|---|---|
| 二维 **< 50 次** | **归因成立,GS3.2 的前提为真** ⇒ 建二维路径是值得的 |
| 二维 **≥ 200 次**(即与 480 同量级) | **归因被证伪** ⇒ 病根在**面内加密梯度**,而它在二维里同样存在;**GS3.2 不会交付它承诺的 AMG 改善**,门需重写 |
| 50–200 之间 | RECORDED,两种来源都有份,按比例判断值不值 |

**同时必须记录**(不作判据):两张网格的**边长比分布**,分面内与 z 向 ——
审计的 "300:1" 到底落在哪一侧,是这次要回答的第二个问题。

## 4. 边界

本轮**不建**二维求解器,**不动库代码**;它只回答"该不该建"。
若前提被证伪,本轮的产出就是那个否证 + 门的重写建议,交使用者裁决。
