## 1. 为什么必须先把**全部**门量测出来再动手

b7 的跨声速门**故意不断言 `converged`**(docstring 写明:跨声速 Picard 的尾巴停在 ~1e-6),
它断言的是**五条**:`0/0 clamps` + `|R| < 1e-4` + `1.0 < M_max < 2.5` + `Γ_min > −1e-3`
+ 外侧 Γ 单调。**pytest 在第一条失败就停**,于是门控日志只报了 clamps 的 `(0, 3)` / `(0, 2)`。

★ **若照着那条日志把 0/0 放宽成 0/3,就会是粉饰** —— 实测下面显示 M1 那条**同时**在残差、
峰值马赫、环量正性上失格。**先测全,再定门。**

## 3. 归因:**圆角网格**,而且证据是完备的

★★ **M1 flat 跨声速五条全过** ⇒ 已提交的锚点在**平截**网格上原样复现,
而同一配方在**圆角**网格上五条里坏三条。**归因完备,不是推断。**

★★ **最刺眼的一条:M∞ = 0.5 时 M1 round 的 M_max = 1.4022,而 flat 只有 0.7726。**
亚声速来流下出现**伪超声速斑块** —— 圆角帽把 P13 翼尖自由边奇点**解了出来**。
这才是那条亚声速腿不收敛的根:**不是削波**(0/0 clamps),是场里多了一块本不该有的超声速区。

## 4. ★ 新发现的不对称:wake-embedded 比 wake-free 受伤重得多

同一个圆角翼尖,两个网格族的反应**差很远**:

| | **M1**(`onera_m6`,**尾迹嵌入体网格**) | **M4**(`onera_m6_wakefree`,**无尾迹**) |
|---|---|---|
| 亚声速 | **✗ 不收敛**,M_max **1.40**(伪超声速) | **✓ 5/5 全过**,M_max 1.06 |
| 跨声速 | ✗ **五条坏三条**(\|R\|、M_max 2.85、Γ_min) | ✗ **只坏两条**(M_max 2.67 出带、0/2 clamps) |

**假设(未测,登记)**:M1 的尾迹片**嵌在体网格里**,而尾迹的**自由边正终止在翼尖** ——
圆角帽改变了那个终止处的几何,于是 P13 奇点在 M1 上被放得更大。M4 没有嵌入的尾迹片,
只吃到圆角本身的代价。⇒ **这是可测的**(把 M4 族也生成 `_flat` 变体做对照),**本轮不做**。

## 5. 新的门(在改测试之前固定)

| 测试 | 处置 | 理由 |
|---|---|---|
| **M1 亚声速** | **`strict=True` xfail** | 圆角网格在 M∞0.5 就有 M_max 1.40 的伪超声速斑块 ⇒ 无可锚状态 |
| **M1 跨声速** | **`strict=True` xfail** | 五条坏三条,不是"多了 3 个 floored" |
| **M4 跨声速** | **`strict=True` xfail** | M_max 2.6669 **出带**(1.0–2.5)且 0/2 clamps;门的物理性保证**就是**那条 0/0,放宽等于取消保证 |
| **M4 亚声速** | **不动** | 它**通过**(5/5),不在失败之列 |

★ **为什么一律 xfail 而不是重锚**:这条门**不断言 `converged`**,它的**全部**物理性保证就是
`0/0 clamps` 与 `M_max ∈ (1.0, 2.5)`。把 clamps 放到 0/3、或把上界抬过 2.85,
等于**把翼尖伪影本身锚进门里**(GS1.4:带限幅的状态不是解;roadmap §3:不得把解不出来的
工况改成解得出来的来过门)。**xfail 是如实,重锚是粉饰。**

★ **strict 是故意的**:将来若圆角侧被治好(例如给 LS 路径做出可用的翼尖处理),
这些必须**变红**逼人重锚,而不是悄悄变好。

★ **平截的读数不丢**:M1 flat 的 5/5 与全部数字记在本文件与
`bench/gate_results/b7_reanchor.csv`,它证明**已提交的锚点仍然正确 —— 只是不再适用于生产网格**。
