## 1. 登记项:路线 (a) 是**推迟,不是取消**

**(a) = 真二维路径(三角形单元)**,`20260802-0800` §4 的那一行。
它比 (b) 多拿的是 **DOF 减半 + 单元数 3× 少**,这是 (b) **给不了**的。
**推迟,不取消。触发条件(任一成立即应重开):**

1. (b) 做完后二维单点**仍 ≥ 1 s**(即迭代那一项不足以达成 GS3.2 的时间验收);
2. 出现需要**大量**二维算例的工作(参数扫掠 / 优化 / 包线),此时 DOF 与单元数的 2–3×
   变成主导成本;
3. 二维路径本身成为交付物(产品要求 2-D 单点 < 1 s 之外还要更快)。

## 2. 为什么 (b) 可能奏效(病因已测清)

`20260802-0800` 测到:**面内梯度 306:1 在二维里一模一样存在,而二维只要 14 次**
⇒ 病因不是面内梯度,是**均匀 z 层与面内梯度相乘**造成的
**三维长宽比 ~0.3..96、且方向随位置翻转**。
⇒ 这是**各向异性 AMG 的经典难题**,而现有 `build_amg_preconditioner` 用的是
`pyamg.smoothed_aggregation_solver(A)` 的**全默认**设置 —— 连
strength-of-connection 阈值都没调过。**先试默认之外的设置,是最便宜的一步。**

## 3. 协议(执行前固定)

**扫描对象**(全部走 `pyamg.smoothed_aggregation_solver` 的现有参数,**不写新算法**):

| 变量 | 试的值 | 为什么 |
|---|---|---|
| `strength` | `('symmetric', theta=0.0/0.25/0.5)`、`'evolution'`、`'affinity'` | 各向异性下"强连接"的判定是核心;`evolution`/`affinity` 是为此设计的 |
| `smooth` | `'jacobi'`(默认)、`'energy'` | energy-min 延拓在各向异性上通常更稳 |
| `presmoother`/`postsmoother` | `gauss_seidel`(默认)、`block_gauss_seidel`、多扫 | 线/块光滑是半粗化之外的标准手段 |
| `max_coarse` / `aggregate` | 默认 vs `'standard'`/`'lloyd'` | 聚合方式影响拉伸方向的粗化 |

**判据(事前固定)**,在 `bench/run_gs32_premise.py` 的**同一口径**上测
(同网格、同 Laplace、同 Dirichlet、同 rtol 1e-8、同 rhs 种子):

| 条件 | 结论 |
|---|---|
| 2.5-D medium 迭代 **< 50** | **达成 GS3.2 的 AMG 条款**(它的原文就是 "< 50"),(b) 交付 |
| 50 ≤ 迭代 < 150 | **部分**:记录改善倍数,(a) 的触发条件 1 更可能成立 |
| 迭代 ≥ 150(即 278 的一半以上) | (b) **失败**;病因不是参数可及的,(a) 或半粗化实现成为唯一路 |

**同时必须记录**:AMG setup 时间(参数更贵的设置会把迭代的节省吃掉)、
**总时间**(setup + CG)才是真指标 —— 迭代数少但 setup 翻倍是**假胜利**。

## 4. 答案不变性(载重条件)

(b) 是**纯预条件子**改动 ⇒ **答案必须不变**。用本阶段刚建立的判据:
在 M6 medium 与 NACA 2.5-D medium 上,`cl_p` / `cl_KJ` / LE 带 RMS / 池化 RMS
相对差 **≤ 1e-8**(`M_max` 依 2026-08-02 裁决不计入)。
**任一超差 ⇒ 不采纳该设置** —— 预条件子改动移动答案,说明它同时改了迭代路径与冻结选择,
那正是 GS3.1 刚刚花一整轮弄清楚的机制。
