## 4. 加密使包线单调下降 —— 不是求解器退化

naca 0.78 → 0.75 → 0.70(coarse/medium/fine);conf_wing 0.84 → 0.65;
ls_wing 0.84 → 0.60;wb 0.75 → 0.65(conf)、0.50 → 无(ls)。

机制:加密解析出更尖的局部峰值,于是**先绷断的那个判据绷得更早**。这一点意味着
**「能力」不能报成一个数,必须按网格层报** —— 这也是把网格密度作为轴的收获。
(Track B 早有同类记录:LS wing-body medium ceiling 0.775 < coarse 0.84。)

⇒ 这是我第三次用「不可比基线上的代理量」设计判据(前两次:GS 阶段的 G1、G1'a)。
**列为模式,不当挡箭牌。**

## 6. 过程中发现并修掉的缺陷

1. **stale import 杀掉整个作业**:`wall_forces` 在 `post.unified` 而非
   `post.surface`,且那句在 `try` **之外** —— 一个后处理 bug 杀掉了数小时的作业。
   后处理已移入 `_postprocess()` 走同一失败纪律,并加了 `done_cells()` 断点续跑。
2. **CSV 让一行声称了它没达到的马赫数**:`ls_naca_medium` 的 "M0.78 NOT_CONVERGED"
   实际状态在 `m_attained = 0.765`,而 `res_final` 1.58e-10 让它看着像擦边未达。
   新增 `m_attained` / `accept_reason` / `res_unfrozen` / `f_final` / `descent10`,
   并把「CLEAN 但马赫不符」变成不可表达(`MACH_NOT_ATTAINED`)。
   ✔ 损害有界:CLEAN 行的 conv 本就要求 `|m_final − m| < 1e-9`,**已有包线点都是真的**。
3. **我给用户看了一个不完整的数字**:把 `conf_wb_coarse` M0.78 α2.0 的 |R| = 9.05e-11
   描述成「擦边」,而它**本来就 < tol 1e-10**;真正的失效是
   `accept_reason = sigma_transport_not_converged`(Kutta 残差 6.5e-15 极好,
   `residual_unfrozen` 9.66e-10 = 冻结残差的 10 倍且超 tol)。
   ⇒ 用户基于此给出的「判为通过」裁决,其对象并不存在。

`ls_naca_medium` 的「还在以 800 倍/10 步下降但没时间了」是两种病,先前在 CSV 里
长得一样。
