## 0. ★★★ 可行性先核清（照今天的常设）：**`rho_floor` 的单元在返回值里定位不了**

在一个 xcoarse 解上实查：
- `result['workspace']` 里**没有任何** `rho`/`nu`/`floor`/`tilde`/`mask` 相关属性（实测属性列表为空）；
- `rho_floor` 封的是**人工密度** `ρ̃ = ρ − ν·g·(ρ − ρ_up)`（`kernels/upwind.py:310`），**`ρ̃` 不被返回**；
- 能拿到的只有 **`clamp_history`（形状 (步数, 2) = [n_limited, n_floored] 逐步）** 与最终 `φ`。

⇒ **①「floored 单元在哪」用现有返回值答不了。** 这不是本轮的失败，是**一处被命名的库仪器缺口**：
★★ **CLAUDE.md 的 clamping 签名写的是 `n_limited`/`n_floored` > 0「**and where those cells are**」，
而库对 floor 那一半只返回计数** ⇒ **这条纪律对 `n_floored` 在当前库上无法执行。**
★ 定位它需要重算 `ρ̃`，而那要求冻结的 donor map 等状态，**同样不被返回** ⇒ 属库改动，本轮不做。

**因此 ① 改为可测的三问**（判据见 §2），并把上面这条作为 **F-GAP** 正式记下。

## 2. 判据

### ② limit_cycle
- ★★★ **L-MECH（binding）**：报**冻结选择**类诊断 —— `assignment_cycle`、`n_freeze_refresh`、
  `n_freeze_reverts`、`n_assignment_stale`、`n_gmres_stalled`、`accept_reason`、`sigma_freeze_report`。
  | 结果 | 读法 |
  |---|---|
  | `assignment_cycle` True 或 freeze refresh/revert 计数显著 > 对照腿 | **frozen-selection churn**（CLAUDE.md 对 limit_cycle 的映射）成立 |
  | 上述全部与对照腿相当、而 `n_gmres_stalled` > 0 | **ill-conditioning**，映射改判 |
  | 两者皆否 | **UNDEFINED**，如实记，不硬归因 |
- **L-PERIOD（RECORDED）**：残差尾部是否**重访**同一组值（报到 4 位有效数字的重访计数与周期）。
  ★ **不设阈值判定** —— 固定阈值是标定（CLAUDE.md 的 descent10 先例）。
- ★ **L-WHERE（RECORDED）**：0 钳制 ⇒ 没有限幅足迹；改报**最终 `max M` 的位置**与后缘区读数，
  与 R14 的三级对照并列。

### ① rho_floor 腿
- **F-WHEN（binding）**：从 `clamp_history` 报 **floored 何时出现/消失**，以及它与 capped 的**共现关系**。
  | 结果 | 读法 |
  |---|---|
  | floored 只在若干步出现且与 capped 同步 | **同一次发散的两端**（速度上限 + 密度下限） |
  | floored 持续存在而 capped 不 | **两个不同的病** |
- **F-CAP-WHERE（binding）**：用 R14 已验证的方法（`q2_at_mach`，1135=1135）定位那 **2587** 个 capped 单元。
  ★★ **修掉 R14 的分带缺陷**：分带必须**覆盖整个 x 范围**（含尾迹），并**断言各带份额之和 = 1**。
- **F-SEED（binding）**：与 C=1.0/seed 0（缓存，0 floored）逐项对比 —— **同 C、只差种子**，差在哪。
- **F-GAP（RECORDED）**：§0 那条库仪器缺口，连"要补什么才能定位"一起记。
