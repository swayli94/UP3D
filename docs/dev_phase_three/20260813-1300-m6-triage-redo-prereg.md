| 事实 | 后果 |
|---|---|
| 搬到 **α = 0** 的**唯一理由**是"躲开多解" | 那是一个**前提**,不是已知事实 |
| ★ **我从未证实 M6 在多解区** —— 多解只在 **2.5-D NACA0012** 上测过;分诊 ① 因**三腿全不收敛**给出 **UNDEFINED** | 前提**未测** |

那样既省下迁移成本,又保住了工况的物理相关性。
★ 这**不是缩小使用者定的范围**,而是**把它排在前提之后**:
在一个未测的前提上做迁移,得到的结论无法归因(本会话已经为这一类混淆付过多次代价)。

**若前提成立(M6 确实多解)⇒ α=0 迁移在本轮判定里被 ARMED,并另行预注册。**

## 3. 事前判据

**主量**:平衡面板上 **cl_p / cl_KJ 相对散布** 与 **LE 上表面 RMS 相对散布**。

| | 条件 | 判定与后续 |
|---|---|---|
| **T1** | cl 散布 **≤ 0.5 %** **且** LE 上 RMS 散布 **≤ 2.5 %** | ⇒ ★ **M6 生产配置下不是多解的** ⇒ **α=0 迁移不必做**;新预算(LE 上 70.35 %)可直接当锚点用;LE 工作在**原工况**上推进 |
| **T2** | cl 散布 > 0.5 % **但** LE 上 RMS 散布 ≤ 2.5 % | ⇒ **升力是多解的载体,LE 亏空与它可分离**(协议 §3 的假设在 3-D 上成立)⇒ LE 工作可在原工况推进,而**每个 3-D 升力数要改报集合** |
| **T3** | **LE 上 RMS 散布也 > 2.5 %** | ⇒ **LE 亏空本身受多解污染** ⇒ ★ **ARM α=0 迁移**(使用者的第 3 步),另行预注册 |
| **T4** | 平衡面板 < 2 条 | ⇒ **UNDEFINED**,RECORDED,不宣称方向 |

**守卫**

- **G-R**:seed 0 那一行即参照;**另两条腿必须在同一脚本/级别/线程/代码下产出**
  (由脚本打印的线程数与 `git status` 干净共同证明);
- ★ **G-D(确定性)**:两条新腿里若有任一与 seed 0 **逐位相同**,则**记为"该种子未进入求解"**
  而不是"稳定" —— 分诊 ① 已实测 **seed 0 与 seed 12 在 2.5-D 上逐位相同**,所以这不是假想;
- **G-C**:不得覆盖 `m3_budget_head_medium.csv`(它是 seed 0 的证据)⇒ 新腿写**带种子的文件名**。
