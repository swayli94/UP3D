## 1. 结论摘要

**一句话**：这个项目的**无粘亚声速部分是健康的**，**网格、尾迹/Kutta、雅可比、
计时仪表、证据文化都是资产**；但它在三个地方走偏了，而且偏的地方正好是产品价值
的全部所在——

1. **跨声速激波算子不收敛**（§4.1，最致命）。三个层次的实测：
   * **同一网格同一工况**，只改人工耗散常数 `upwind_c`（1.0→6.0），全部是收敛解：
     升力差 **26%–47%**，激波位置差 **0.06–0.07 弦长**；
   * **同一工况同一默认参数，只加密网格 3.6 倍**（项目自己挑选的"祝福工况"
     NACA0012 M0.7875）：升力 **0.373 → 0.523（+40%）**，激波
     **0.564 → 0.674（后移 0.11 弦长）**——两个都是残差 1e-11 量级、带二次收敛
     尾巴的"合格解"。**这一条不需要任何外部参考值，是解自己和自己矛盾。**
   * 经典工况 M0.80 在中等网格上，C=2.0 的收敛解给出 cl **0.724**，激波跑到
     0.80 弦长（我记忆中的 Euler 值约 0.36，见 §3.1 的出处说明）。

   一个跨声速全速势求解器，如果激波位置由调参和网格决定而不是由方程决定，那么后面
   所有的三维、翼身组合体、粘性耦合工作都建在沙子上——而这正是过去大半年的工作量
   所在。
2. **速度差的不是语言，是线性代数策略**（§4.3）。组装（Numba）只占 1.4% 的墙钟。
   真正的成本在把**稀疏直接 LU 当预条件子**：M6 medium 上一次 `splu` 分解 6.5 s、
   填充膨胀 55 倍、每次回代 36 ms；而同一个矩阵用仓库里现成的 AMG+CG 只要
   **15 次迭代 / 0.17 s**。我拿项目自己的 G8.2 配方做了对照，**只把 `precond`
   从 `"direct"` 改成 `"amg"`：M6 medium 从 108 s 降到 31.7 s（3.4×），
   cl_p / γ / M_max 一个数字都没变**。剩下的 31.7 s 里还有 13.6 s 是 Picard 种子，
   去掉马赫爬坡后 **15–20 s 是现成可拿的**（相对项目已记录的 149 s 约 8–10×）。
   粘性端到端的差距更大（12 479 s 且不收敛），主因是 §4.4 的选型，也不是语言。
3. **粘性模块选了最难的一条路**（§4.4）。直接上 Drela 2013 的**三维**积分边界层
   （每节点 6 个未知量、两个剪应力输运方程、横流），结果：在 M6 中等网格上边界层
   本身花 **1032 s**，而无粘 Newton 只花 115 s——边界层比无粘贵 **9 倍**（正常
   应该是 1% 以下）；二维对 XFOIL 的 δ* 误差最大 28%、Δcl 只有 XFOIL 的 54%；
   三维松耦合不收敛、紧耦合卡在"IBL 残差地板"上（为此连开了 GV5.1/1b/1c/1d/5.5/5.6
   六个阶段）。而项目自己测出来横流只有 max|B|/|A| ≤ 0.072——**为横流付的复杂度
   代价基本没用上**。

**还有一个元层面的问题**（§5）：门禁（gate）体系变成了**自我一致**而不是**对外
求真**。同一个 NACA0012 M0.80/α1.25 算例，G4.1 门禁要求激波在 0.62±0.03（对标
Euler），Picard 路径给 0.604 通过；G8.1 门禁把 Newton 路径的 0.658 锁成"真正的
离散解"——**0.658 在 G4.1 的带子外面**，但两个门禁同时是绿的，因为它们是两个不同
的门。当两条路径打架时，处理方式是把其中一个的数值锁成基准、并把打架的工况
（medium M0.80）改成不打架的工况（M0.7875），而不是去追究哪个对。

## 3. 实验数据

### 3.1 exp1 + exp3 + exp6：跨声速答案是"调出来的"

工况：NACA0012 2.5-D，M∞ = 0.80，α = 1.25°——这是 AGARD/GAMM 的经典标定算例，
也是项目自己 `cases/reference_data/naca0012_m080/` 的对标算例。

**关于参考值的出处，先说清楚**（这关系到下面结论的可靠性）：
* **激波位置 0.60–0.63** 是项目自己已提交的参考 CSV（`shock_reference.csv`，
  门禁带 0.62±0.03，出处在它的 README 里），这是本报告用的**主要标尺**。
* **cl ≈ 0.36** 是我记忆中该算例的经典 Euler 值（FLO52/AGARD 系）；**项目的参考
  CSV 里没有 cl 锚点**，所以这个数请你自己再核一遍，我不把结论压在它上面。
* **最强的那条结论完全不需要任何外部参考**：见本节末尾"同一工况同一参数、
  只加密网格，升力 +40%"——那是解自己和自己不一致。

粗网格（6 106 节点），全部为**收敛**解（残差 ~1e-11，二次收敛尾巴，0 clamp）：

| 配置 | 激波 x/c | cl_p | cl_KJ | M_max |
|---|---|---|---|---|
| `upwind_c` = 1.0 | 0.695 | 0.532 | 0.541 | 1.431 |
| **= 1.5（出厂默认）** | **0.658** | **0.459** | **0.468** | **1.408** |
| = 2.0 | 0.641 | 0.424 | 0.433 | 1.387 |
| = 3.0 | 0.640 | 0.390 | 0.399 | 1.350 |
| = 4.0 | 0.643 | 0.375 | 0.383 | 1.323 |
| = 5.0 | 0.658 | 0.366 | 0.374 | 1.303 |
| = 6.0 | 0.662 | 0.361 | 0.369 | 1.288 |
| `m_crit` = 0.90（默认 0.95） | 0.624 | 0.404 | 0.412 | 1.372 |
| `m_crit` = 1.00 | 0.687 | 0.534 | 0.543 | 1.437 |
| Picard 路径（G4.1 配方，140 s） | 0.604 | 0.357 | 0.364 | 1.373 |

读法：
* 默认参数的收敛解 cl = 0.459，比 Euler 锚点高 **27%**；激波 0.658 **落在项目
  自己 G4.1 门禁带 [0.59, 0.65] 之外**。
* 把 `upwind_c` 从 1.0 调到 6.0，cl 从 0.532 单调降到 0.361，**要 C ≈ 5–6 才对得上
  Euler 锚点**——而 `design.md §3` 引文献给出的合理范围是 **C ∈ [1, 2]**，出厂默认 1.5。
* 项目文档里写这个解"dissipation-scan robust（upwind_c 2.0→1.5）"。我实测这两个值
  之间 cl 差 **8%**、激波差 0.017c。对一个要预测 2–3% 升力变化、0.02c 激波移动的
  粘性修正来说，这不叫 robust。
* Picard 路径（也就是产出 G4.1 已提交证据的那条路）反而最接近真值。项目文档把它
  判为"停滞在非解上"（Newton 残差 2.2e-4，这点是对的），于是把 Newton 的
  0.459 锁成基准。**两条路径的差 (0.357 vs 0.459) 从来没有对着外部真值裁决过。**

中等网格（21 874 节点，加密 3.6×）：

| 工况 | 配置 | 激波 x/c | cl_p | 收敛？ |
|---|---|---|---|---|
| M0.80 | C = 1.0 / 1.5 | — | — | ✗ 马赫爬坡在到达目标前就死了 |
| M0.80 | C = 2.0 | **0.802** | **0.724** | ✓ |
| M0.80 | C = 3.0 | 0.731 | 0.573 | ✓ |
| M0.7875（祝福工况） | **C = 1.5（默认）** | **0.674** | **0.523** | ✓（= 项目 G8.1 锁定值，我复现到 4 位） |
| M0.7875 | C = 2.0 | 0.652 | 0.486 | ✓ |
| M0.7875 | C = 3.0 | 0.631 | 0.444 | ✓ |
| M0.7875 | C = 4.0 | 0.612 | 0.419 | ✓ |
| M0.7875 | C = 5.0 | 0.611 | 0.403 | ✓ |

**两个最关键的数字**：

* **同一工况、同一默认参数、只加密网格**（M0.7875，C=1.5）：
  粗 `cl 0.373 / 激波 0.564` → 中 `cl 0.523 / 激波 0.674`。
  **升力 +40%，激波后移 0.11 弦长。** 两者都是"收敛"解。
  → 这个求解器在它自己的旗舰二维工况上**没有网格收敛的跨声速解**。
* **经典工况 M0.80 在中等网格上**，C=2.0 给出 cl **0.724**、激波跑到 80% 弦长，
  而且是收敛解；C=3.0 给 0.573。（对照我记忆中的 Euler 值 ~0.36 是高一倍，
  这个锚点请你核实；但即使不看锚点，0.573 与 0.724 之间的分歧本身就说明
  "这个离散问题在这个工况下的收敛解"没有唯一含义。）

项目对此的解释是"FP 非唯一性折叠（Steinhoff–Jameson）"，并记录了
`M0.775 → cl 0.396；M0.7875 → cl 0.523`（dcl/dM ≈ 10）。我的看法（§4.1 详述）：
**按项目自己 `design.md §1` 写的，FP 非唯一带在 M∞ ≈ 0.82–0.85 且低升力**——
现在这个"折叠"出现在 M0.78–0.80、α=1.25°，比自己文档写的带子低 0.04 马赫；
而 Euler 在这个马赫附近的 dcl/dM 大约是 0.5–1（我的估计量级，可核）。
一个提前 0.04 马赫出现、斜率大一个量级的"折叠"，更像是**激波耗散量级不对**
造成的离散多解，而不是模型物理。

### 3.2 exp5：一次椭圆求解到底多贵（速度的下限）

用仓库里现成的 `build_amg_preconditioner` + CG，收敛到 rtol 1e-8；`splu` 用同一个矩阵：

| 网格 | 自由度 | AMG 建立 | CG+AMG | splu 分解 | 填充膨胀 | splu 每次回代 | 残差组装 | 矩阵组装 |
|---|---|---|---|---|---|---|---|---|
| NACA 2.5-D medium | 21 696 | 0.034 s | **480 次 / 1.20 s** | 0.11 s | 8.1× | 1.7 ms | 4.2 ms | 5.0 ms |
| M6 coarse | 12 755 | 0.030 s | **13 次 / 0.031 s** | 0.23 s | 25.4× | 3.2 ms | 4.6 ms | 7.1 ms |
| M6 medium | 70 219 | 0.196 s | **15 次 / 0.171 s** | **6.5 s** | **55.4×** | **35.6 ms** | 7.1 ms | 9.5 ms |
| 翼身组合体 medium | 134 603 | 0.397 s | **16 次 / 0.40 s** | **12.7 s** | 55.6×（1.04 亿非零） | **72.8 ms** | 11.8 ms | 16.2 ms |

读法：
* **三维机翼网格上 AMG 非常好**：13–16 次迭代、线性扩展。一次椭圆求解 0.17 s
  （M6 medium）/ 0.40 s（翼身组合体）。一个正常的 Newton-Krylov 全速势求解，
  总共相当于 20–40 次这种求解 → **算法下限是 M6 medium ~10 s、翼身组合体 ~25 s**
  （§3.3 实测换成 AMG 后已经拿到 31.7 s，其中 13.6 s 还是可去掉的种子开销）。
* **出厂配方却用 `precond="direct"`**：M6 medium 一次 LU 6.5 s（我实测；项目自己
  记录的 Newton 雅可比 LU 是 18.6 s，非对称填充更多），每次 GMRES 迭代要付 36 ms
  的回代。项目的"优化"是**把 LU 滞后重用**（`direct_refactor_every=1000`），
  而不是换成 AMG。
* **2.5-D 那张网格是唯一 AMG 表现差的**（480 次迭代）——它是"把二维问题拉伸成一层
  三维棱柱再切成薄片四面体"的产物，各向异性极端（边长跨 300:1）。项目的求解器策略
  是在这张病态网格上标定的，然后被带到了 AMG 本来很好用的三维算例上。**用一个自己
  造出来的病态测试例，决定了整个项目的线性代数路线。**

### 3.3 exp2：换一个预条件子，端到端省多少

用项目自己的 `NEWTON_M6_RECIPE`（G8.2 配方，M0.84/α3.06）原样跑，
**只改 `precond` 一项**（16 线程，机器空闲）：

|---|---|---|---|---|---|---|---|---|---|---|---|---|
| M6 coarse | direct | 6.73 s | 17 | 2.43 | 0.32 | 1.08 | 2.30 | 234 | 0.256048 | 0.08311 | 1.3975 | 6.9e-12 |
| M6 coarse | **amg** | **4.11 s** | 17 | 2.36 | 0.24 | **0.29** | **0.85** | 217 | 0.256048 | 0.08311 | 1.3975 | 7.6e-12 |
| M6 medium | direct | 108.3 s | 18 | 13.4 | 1.63 | **43.3** | **47.0** | 375 | 0.264637 | 0.085048 | 2.1288 | 6.5e-15 |
| M6 medium | **amg** | **31.7 s** | 18 | 13.6 | 1.71 | **2.08** | **12.2** | 636 | 0.264637 | 0.085048 | 2.1288 | 6.8e-15 |

**结论：改一个字符串，M6 medium 快 3.4 倍，答案一个数字都没变**
（cl_p、γ、M_max 完全相同，残差同量级；`cl_p 0.264637` 也和项目已提交的
A1 记录 `0.26464` 一致，说明我这次复现是对的）。

再往下看剩下的 31.7 s：**种子（Picard 预热）13.6 s = 43%**，线性求解 12.2 s，
预条件 2.1 s，组装 1.7 s。也就是说去掉马赫爬坡、换个更便宜的初值策略之后，
**M6 medium 无粘落到 15–20 s 是现成可拿的**，不需要动任何物理。

顺带一个值得注意的数字：这个"收敛、0 limited、0 floored、残差 6.5e-15"的解，
**M_max = 2.13**——而 `design.md §1` 自己写的适用范围是"局部激波 M ≲ 1.3"。
这个 2.13 是翼尖尾涡面自由边奇点（项目命名 P13）的局部伪影。它不一定污染中段
剖面的 Cp，但它意味着 M_max 这个诊断量长期以来是没有意义的，而项目用它做过

## 4. 根因分析

### 4.1 跨声速激波算子：最致命的一处

**代码在做什么。** `kernels/upwind.py`：对每个四面体 e，
`ρ̃_e = ρ_e − ν_e·G·(ρ_e − ρ_up)`，其中 `ν = C·max(0, 1 − M_c²/M²)`，
`ρ_up` 由**面邻居多跳游走**（最多 4 跳，每跳选最逆流的面邻居，目标走到"本单元
流向跨度的 0.8 倍"）选出，`G` 是一个"reach 补偿增益"，被夹在 `[1, reach_gain_max]`。

**为什么这不成立。** 经典 Hafez–South–Murman/Holst 的式子是
`ρ̃ = ρ − ν·Δℓ·(∂ρ/∂ℓ)`，其中 **Δℓ 是流向的局部网格尺度**。这里把
`Δℓ·∂ρ/∂ℓ` 近似成 `ρ_e − ρ_up`，于是**有效耗散正比于"游走恰好走了多远"**。
在他们的网格上（棱柱切分的薄片四面体，长宽比到 9+，边长跨 300:1），这个距离
是一个方差极大的随机量，而不是位置的光滑函数。模块自己的注释就承认：单跳只走到
0.25–0.39 个跨度，"有效 ν 掉到 (M²−1)/M² 稳定门槛以下"——所以才加了多跳游走和
增益夹取来救。**这些补丁把"耗散量"从物理尺度里解耦了。**

**这解释了几乎所有下游症状**（每一条都是项目自己记录的）：
* 出厂 C=1.5 需要 3–4 倍才对得上 Euler（exp6）——正是"上游距离欠给 3 倍"的表现；
* 激波系统性偏后：RAE2822 两个工况**每一个**计算激波都在实验区间**下游 0.06–0.10c**，
  而且随马赫/攻角变差、**加密不改善**（GV5.2）；
* M6 机翼加了粘性 Cp **不向实验靠**（"前缘吸力偏浅、激波偏后"，GV5.3）；
* 出现"折叠/非唯一"比文献低 0.04 马赫（§3.1）；
* 需要 M_cap=3 限速器、ρ̃ 地板、选择冻结（freeze）、clamp 计数……这些都是
  "耗散不足 → 局部超速 → 兜底"的连锁；
* 翼身结合处/翼尖出现 M=2.0–5.2 的伪超声速斑块（B18/B20/B26/B30 追了 10 多个阶段），
  正是网格最不规则的地方——和"耗散量依赖网格拓扑"的预期完全一致。

**注意区分**：翼尖那一支还有一个独立的**模型**原因——刚性平面尾涡面在翼尖自由边
上的奇点（项目命名为 P13）。这两件事叠在一起，被当成一系列"不同的坑"追了很久。

**这一处必须先修，而且要用一个便宜的判据来验收**：一维/准一维（收缩-扩张管道
或跨声速小扰动可解算例）里激波位置随 C ∈ [1,3] 变化 < 0.01c、随 h→0 收敛。
现在的项目里**没有任何一条门禁检验"激波位置对耗散不敏感"或"激波位置网格收敛"**——
这是整套 gate 体系最大的漏洞。

### 4.2 壁面 Cp 精度：产品的另一半核心量

项目已记录（G1.6/P11，我未重跑，但证据链完整）：球面纯 Laplace、h=0.08 中等网格，
**max|ΔCp| = 11.6%**，驻点速度 0.197（精确 0），赤道 1.448 vs 1.5（−3.5%）。
P11 试过"弯曲壁单元"（把几何升到二次、场仍是线性），实测只从 11.56% 到 11.33%，
并正确诊断为映射 P1 在二次几何上丢失线性再现（O(h)）。

我的判断：**这个结论"P1 场在 h=0.08 的固有能力"是对的，但它是被选中的路线的后果，
不是不可逾越的物理**。一个以表面压强为唯一交付物的求解器，把场取成节点线性、
壁面速度靠逐三角形常梯度恢复，等于在最关键的量上先扔掉一阶精度。可行的出路
（项目列过但没做）：
* **壁面附近铺各向异性棱柱层**（他们已经有拉伸机器）：既提高法向分辨率，又让壁面
  三角形规整，梯度恢复立刻好转；
* **等参 P2**（几何+场同时二次）——唯一能直接达标的路线；
* 壁面速度用**最小二乘/二次重构**（`wall_tangential_gradient_quadratic` 已存在，
  但不是默认），并用球面算例把验收定成 h=0.08 下 max|ΔCp| < 2%。

### 4.3 线性代数与非线性策略：白送的 3–10 倍

数据在 §3.2/§3.3。三件事：
1. **`precond="direct"` 是三维的错误选择**：填充 55 倍、分解 6.5–19 s、回代 36–73 ms。
   AMG 在同样的矩阵上 15 次迭代 0.17 s。把生产配方换成 AMG 是**改一个字符串**的事，
   实测端到端 3.4×（108 → 31.7 s），答案不变。
2. **2.5-D 拉伸网格污染了策略选择**（480 次 CG 迭代）。二维问题应该有一条真正的
   二维路径（同样的装配代码，三角形单元），而不是"一层棱柱切四面体"——现在为一个
   二维算例付 2 倍自由度、3 倍单元、以及一个 AMG 杀手级的各向异性。
3. **非线性策略过度工程化**：马赫爬坡 + 中间层松容差 + 选择冻结 + 冻结刷新 +
   冻结回退 + 线搜索兜底 + 限速器 + 密度地板 + Γ 割线/Aitken/pressure-Kutta……
   共约 25 个可调旋钮。这些绝大多数是在补 §4.1 的洞。洞补好之后，标准的
   **伪时间推进 + Eisenstat–Walker 非精确 Newton + AMG** 就够了，而且可以直接在
   目标马赫上求解，不需要爬坡（现在光"种子 + 爬坡"就占 31.7 s 里的 13.6 s）。

顺带一个陷阱（我实测发现）：`solve_newton_transonic` 在最高马赫层失败时，返回的是
**更低马赫层**的场，顶层字典里除了 `converged=False` 没有任何标记（我在
M0.80 和 M0.7875 两个请求下拿到了完全相同的 cl_KJ 和 M_max，就是这么发现的）。
调用者只看 `converged` 是安全的，但任何"记录下来当结果"的脚本都会静默产出
错标马赫的数据。

### 4.4 粘性：选型过重，且顺序错了

* **选型**：Drela 2013 的三维 IBL（6 未知量/节点、两个剪应力输运、横流曲率项），
  `ibl3.py` 1615 行 + `closures.py` 1053 行。而项目自己测出机翼上
  **max|B|/|A| ≤ 0.072**——横流几乎可以忽略。付了三维的代价，拿到的是准二维的物理。
* **成本**：M6 medium 上 IBL 1032 s，无粘 115 s。BLWF 类工具里边界层是"免费"的
  （沿弦向条带推进，微秒级）。用 `scipy.spsolve` 解 6×6 块的全场耦合系统 +
  伪时间，是把一个可以显式行进的问题做成了一个大稀疏隐式问题。
* **顺序**：二维还没对上（δ* 误差 28%、Δcl 只有 XFOIL 的 54%、跳变站 cf +44%）
  就上了三维机翼，机翼还没收敛就上了紧耦合，紧耦合卡住就连开六个阶段去追
  "IBL 残差地板"和"二次收敛窗口"。**而这些追问的前提——无粘激波位置是可信的——
  在 §4.1 已经不成立。** 例如 GV5.2 的结论"松耦合的位移厚度反馈在 M≥0.725 太弱"，
  完全可能只是"无粘激波本来就偏后 0.06–0.10c，粘性修正量级根本补不上"。
* **正确的耦合方式没用上**：松耦合在分离区必然发散（他们测到的 ṁ 跑飞 ×12.4），
  这正是 Veldman 准同时/交互律要解决的经典问题，大约几十行代码，比"增广 Newton +
  Schur 预条件"（GV5.4/5.6 两个阶段、结论都是 FAIL）便宜两个数量级。

### 4.5 缺失的产品能力

* **阻力**：`cd_pressure` 有，但文档自称"明确不可信"，**没有任何阻力门禁**，
  没有远场/动量阻力分解，没有摩擦阻力输出，没有极曲线流程。对标 BLWF 的话，
  这等于交付物没做。
* **用户接口**：无 CLI、无 `entry_points`、无输入文件格式（yaml/json 都没有）。
  想算一个新构型，得写 Python 脚本、自己拼 8–10 个函数调用和 25 个旋钮。
* **收敛/健壮性包线**：没有"扫一遍 M×α 20 个点、100% 收敛、0 clamp"这种门禁。
  现在的"能力"表述是"某个网格某个马赫达到了"，靠人工记录。

## 5. 流程、文档、测试层面的问题

**规模先摆出来**：库代码 23 k 行，测试 15 k 行，cases 脚本 41 k 行，
**Markdown 文档 96 个文件 33 141 行**（其中 `PROJECT_STRUCTURE.md` 123 KB、
`agent-rules.md` 1 500 行、`roadmap/track_b.md` 3 008 行）。文档比库代码还长 40%。

1. **门禁自洽，但不对外求真**。§1 已举例：G4.1 和 G8.1 对同一算例的要求互相矛盾，
   两个都绿。机制上的原因是"把实测值锁成 regression lock"——一旦锁进去，后续的
   变化就变成"新的锁"，而不是"和真值的偏差变大了"。
2. **把伪影锁成基准**。G8.1 的注释写着 0.658/0.459 是"the TRUE discrete solution…
   NOT the P4 Picard stall state 0.604/0.334"。Picard 那个状态确实不是离散解（残差
   2.2e-4，这个诊断是对的）；但结论只能是"两条路都还没资格当基准"，不能是"更收敛
   的那个就是真的"——尤其当它落在自己参考带外、M_max 1.408→1.459 已经超出
   `design.md §1` 自己写的"局部激波 M ≲ 1.3"适用范围时。
3. **回避而不是解决**。medium M0.80 不可解 → 把门禁工况改成 M0.7875。
   这条决定被完整记录、理由充分（"在折叠边缘"），但它让旗舰算例从此不再被检验。
4. **微观问题吸走了全部预算**。V5 一个阶段里连开 GV5.1/1b/1c/1d 四个门去测
   "增广 Newton 有没有二次收敛窗口"，答案是"没有"，代价是四个阶段 + 数千行文档；
   V6 整个阶段做尾迹面 δ* 源项，实测效果 Δcl = **+0.00015（+0.05%）**，比自己的
   噪声地板低 20 倍。这些都是**在 §4.1 的洞没补之前**做的精细化工作。
5. **"bit-identical"测试纪律反噬**。全套 605 个测试函数里，约 44% 的测试文件含
   bitwise 相等断言。这次在一台干净机器上，**5 个失败纯粹来自最后一位舍入**——
   我量化了其中一个：`test_p8_jacobian` 里 4051 个矩阵元中 244 个差 **1 ULP**
   （2.2e-16，相对 1.0 的量级）。这类断言：
   * 无法跨库版本/线程数存活（项目自己的纪律 #12 已经承认 numba 缓存加载都不 bit-faithful）；
   * 真正的回归会淹没在这些假警报里；
   * 让"默认关闭的旋钮"必须永久保留（为了保证老数字可复现），于是旋钮只增不减。
6. **两套尾迹模型 + 各自的 Picard/Newton 孪生 = 4 个非线性驱动器**。Track B 从
   B16 到 B32 共 17 个阶段，几乎全在处理 level-set 的病理（远场 aux 近奇异、
   翼身结合 pocket、翼尖自由边、weld sign……）。这些工作质量很高，但服务的是
   一个**还没证明比 conforming 更好**的第二条路线。
7. **文档的可读性已经崩了**。`roadmap.md` 号称是"索引"，但单条 bullet 就有 30 多行；
   `agent-rules.md` 的"Current phase"块 1 500 行、每次会话都要加载。这不是给人读的，
   是给"上下文"读的——而它挤掉的正是"我们的产品目标是什么"这句话的位置。

## 7. 做得好的、别丢掉的东西

1. **网格生成流水线**（gmsh 脚本 + 质量统计 + 图）：快、可脚本化、有质量门槛。
2. **尾迹切割 + Kutta 机制**，特别是 **P14 的压强相等 Kutta 估计器**——这是一个
   真正的、有量化收益的改进（TE Cp 间隙降 55–67×，两条路径的升力从差 4.5% 变成
   差 0.17%）。
3. **精确雅可比 + FD 验证的纪律**（B19 找出的 3-D 列映射错误、V5 的 FD 中位数守卫）。
   这类"导数必须和残差一致"的检查是很多 CFD 项目缺的。
4. **计时仪表（A1）**：per-phase 墙钟分解是这次审计最有用的现成数据。
5. **证据文化**：一个数字必须有提交的产物。我能在半天内独立复现 G8.1/G4.1/A1 的
   关键锁定值（到 4–6 位），全靠这条。很多项目做不到。
6. **诚实记录负面结论**（P11 的弯曲单元、B24 的水线延伸、GV5.x 的一串 FAIL）。
   这条非常可贵——问题不在于诚实度，而在于**选题**。

## 8. 如果重新出发：我建议的路线

### 8.1 先把"验收标准"从门禁改成产品指标（半天）

把下面 5 条写在一页纸上，其他所有 gate 都从属于它：

| 指标 | 目标 | 现状 |
|---|---|---|
| **A. 二维无粘标定** | NACA0012 M0.80/α1.25：激波 0.61±0.02（用项目现有参考带），cl 落在核实过的 Euler 锚点 ±5%，**且两级网格都满足**，**且 C∈[1,3] 内变化 <0.01c** | 全部不满足 |
| **B. 二维粘性标定** | RAE2822 case 9/10：激波位置 ±0.02c，cl ±3%，cd ±10 counts，单点 < 10 s | 激波偏后 0.06–0.10c，1/4 收敛 |
| **C. 三维无粘** | ONERA M6 M0.8395/α3.06：七站 Cp RMS < 0.05，< 60 CPU·s | RMS 0.13，2400+ CPU·s |
| **D. 翼身组合体粘性** | 一个点（含网格）< 2 CPU·min | 3.5 h 且不收敛 |
| **E. 包线健壮性** | M 0.5–0.86 × α −2…6 共 20 点，100% 收敛，0 clamp，无 M_max > 1.5 | 无此度量 |

### 8.2 修根因，顺序不能换

**第 1 步：跨声速算子（挡住其他一切）。**
把人工密度改成**几何上明确的**通量偏置：对每条边/每个对偶面，用真实的流向网格
尺度 `Δℓ`（流向投影的单元尺寸，不是"游走走了多远"）和最小二乘 `∂ρ/∂s`，
即 `ρ̃ = ρ − ν·Δℓ·∂ρ/∂s`；`ν` 保持 López/Hafez 形式。验收用便宜的准一维算例
（收缩-扩张管道有解析/参考激波位置）：激波位置对 C∈[1,3] 变化 < 0.01c、随 h 收敛。
**这一步做完再碰任何三维东西。** 我 §3.1 的表格可以直接当"修好前"的基线。

**第 2 步：壁面精度。**
优先做**壁面棱柱层**（5–10 层，法向拉伸）+ 把二次壁面梯度恢复设为默认。
验收：球面 h=0.08 时 max|ΔCp| < 2%、驻点速度 < 0.02。这一步同时把 IBL 的输入
（u_e）质量提上去——现在 A4 的"输入误差带 2.5%"本身就压过了粘性效应。

**第 3 步：速度（改配方，不重写）。**
生产配方一律 `precond="amg"`；`direct` 只留给 <5k 自由度的调试。
写一条真正的**二维路径**（三角形单元），别再用一层棱柱冒充二维。
去掉马赫爬坡，改成目标马赫上的伪时间 + 非精确 Newton。
目标：M6 medium 无粘 **< 15 s**（已实测到 31.7 s，其中 13.6 s 是可去掉的种子），
翼身组合体 medium **< 40 s**（依据见 §3.2/§3.3 的实测下限）。

**第 4 步：粘性重启（做减法）。**
* 把三维 IBL 降级为**弦向条带的二维 IBL**（Drela 二方程 + lag，或 Drela–Giles 三方程），
  沿表面弦向线行进，横流忽略（有他们自己 |B|/|A| ≤ 0.072 的实测背书）；
  成本目标：整机翼 < 1 s。
* 耦合用 **Veldman 准同时/交互律**，不要松循环，也不要增广 Newton。
* 先把 RAE2822 case 9/10 打通（数据已在仓库里），再回三维。
* `ibl3.py` 不删，冻结成"研究分支"。

**第 5 步：工程化收尾。**
选一条尾迹路线（按现有证据是 **conforming**：它在翼身组合体上到 M0.84、
两条路线升力一致、且不需要 level-set 的一堆病理修补），删掉另一条 + 它的 Picard 孪生
（约 2 500 行库代码 + 15 个测试文件 + Track B 大半历史债）。
加一个 CLI + yaml 输入。加阻力（远场/动量分解 + 摩擦阻力）。
把 bitwise 断言换成带公差的物理断言 + 少量 golden CSV，钉死环境（lockfile）。

### 8.3 关于"要不要换技术路线"

用户问过"不强求 level-set 或 conforming，哪个成功走哪个"。我的回答分两层：

* **尾迹模型这一层**：走 conforming。证据在仓库里（B27–B32：两条路线最终都到同一个
  能力天花板，而 level-set 为此多付了 17 个阶段的病理修补）。
* **更上面一层**（网格范式），如果 2 CPU·min 的翼身组合体是硬指标，必须诚实面对：
  **非结构四面体 + P1 场，在"每个自由度的精度"上比 BLWF 的贴体结构网格差
  大约 5–10 倍**（这是我的工程判断，不是本次实测；可查的实测支撑是球面 11.6%
  和 M6 七站 Cp RMS 0.13），而 BLWF 还用嵌套网格把点堆在需要的地方。
  也就是说，即使把 §8.2 全部做完，
  达到的可能是"翼身组合体 30–60 s 无粘 + 几秒粘性"，方向对，但要打到 BLWF 的
  2 CPU·min 且精度可比，还需要：**壁面棱柱层（必须）+ 各向异性/自适应加密（很可能）**。
  如果目标是"尽快有一个能出极曲线的可信工具"，还有一条更保守的路：
  **在机翼/翼身这一类拓扑上生成半结构（C-H）贴体网格**，用同一套 FEM/FV 装配跑；
  几何灵活性用"非结构备用路径"兜。这条路把 §4.1 和 §4.2 两个根因同时变容易
  （规整网格上上游距离和壁面梯度都是良定的）。**这是一个战略选择，需要你来定；
  我的建议是先按 §8.2 第 1、2 步做，因为无论哪条路，这两个洞都必须补。**
