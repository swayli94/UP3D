## 3. 强项，具体点名

不点名的表扬等于没说。以下四条是我认为**应当固化成模板、并向其他门推广**的：

## 4. 洞一 ★★★：**解析真值从不经过生产 Newton 驱动器**

递归查完 `tests/` 内的 helper 之后，C 类九个门的求解路径是：

| 门 | 真值 | 走的求解器 |
|---|---|---|
| C01 MMS · C02 圆柱 · C03 球 | 精确 / 制造解 | `solve_laplace*`（Picard 层） |
| C06 带环量圆柱 · C07 Kármán–Trefftz | 精确（不可压，带升力） | `solve_laplace_lifting` |
| C09 Prandtl–Glauert | 渐近，非真值 | `solve_subsonic*` |
| **C05 准一维喷管**（唯一带激波的精确解） | 精确 | ★ **`tests/_nozzle_case.py::DuctSystem`** |
| **C08 Ringleb**（唯一 2-D 跨声速精确解） | 精确 | ★ **同一个 `DuctSystem`** |
| C04 M1a 三级收敛 | **无真值**（自锚定性质门） | `solve_newton_lifting` |

`DuctSystem` 的 docstring 说得很准确 —— 它用的是**出厂 kernel** 的残差与 Jacobian
（`PicardOperator` / `UpwindOperator` / `EntropyOperator`，冻结 σ 语义也照抄）。
⇒ **离散格式确实对着精确解验过了。** 这条要说清楚，否则会低估现状。

**但驱动器是重写的**，而且差异不是形式上的：

| | 生产 `solve_newton_lifting` | `DuctSystem` |
|---|---|---|
| 线搜索 / 全局化 | 生产策略 + EW forcing + 预条件子 | 12 次减半的自写回溯 + `spsolve` |
| 钳制 | `m_cap = 3.0` + `rho_floor` + **钳制记账**（`n_limited`/`n_floored`） | 只有 `rho_floor`，**没有 m_cap，没有钳制记账** |
| 冷启动种子 / 回退 | `n_picard_seed` + `_SEED_FALLBACK` | 无 |
| **熵修正** | **默认 ON** | ★ **默认 OFF，而 C05/C08 都没有打开它** |
| Kutta / 尾迹 | 有 | 无（Dirichlet 管道） |

★★ **由此产生一处"两个数不是同一件东西"**：C08 把 `upwind_c = 1.5` 那条腿称作
"**生产腿**"，并用它给人工耗散定价（`SUP_RMS_MAX = 0.13`，实测 0.1001）。
它是**生产的 C 值**，不是**生产的配置** —— 熵修正在这条腿上是关掉的，而 A06 实测
熵修正会让峰**更强**（M²max 6.426 ON vs 5.607 OFF）。这正是本季记过五次的那族
（跨 pipeline / 跨档 / 跨线程 / 跨时间 / 跨网格代）**再添一个成员：跨配置**。

### 4.1 为什么补不上：**生产 Newton 没有非升力入口**

`pyfp3d/solve/newton.py` 只导出 `solve_newton_lifting` 与 `solve_newton_transonic`，
两个都要求 wake cut / Kutta。Ringleb 与喷管是**没有尾迹的 Dirichlet 问题** ⇒
**它们在结构上无法调用生产驱动器**，所以当初只能重写一个。
**这不是测试写得随便，是库的 API 形状决定的。**

⇒ 最小修法（建议 1）：把 `newton.py` 的驱动循环与"升力/Kutta"解耦，露出一个
非升力入口，让 C05/C08 走生产策略。**判据形状**：新入口与现有
`solve_newton_lifting` 在任一既有算例上**位相同**（`array_equal(phi)`），这一条
本项目已经做过很多次（R19 的 `gamma_target` 就是模板）。

## 5. 洞二 ★★★：**D 类只有两档 ⇒ 只有参照方有误差棒**

实测：**`tests/D` 的每一个门都只跑 `("coarse", "medium")` 两档**（D05 D06 D07 D08
D11 D12 D13 逐一确认），而 `tests/C` 全部跑三档。

对照参照侧：`cfl3d/*/grid_convergence.csv` 有 **L1–L4 四档**，而且 §8 那一轮专门
给它加了 `ratio` / `implied_order` / `asymptotic`，并把判定改成三分
（`yes` / `no` / **`unstable`**）。

⇒ **不对称是刺眼的**：

> 参照物有四档、有观察阶、有渐近检验、有三分判定；**我方有两档、没有观察阶、
> 没有数值不确定度**。而 D 类每一条判据都写成"我方的一个数 vs 参照的一条带"。

按 ASME V&V 20 的形状，验证比较量是 `E = S − D`，而验证不确定度
`u_val² = u_num² + u_input² + u_D²`。**现在只有 `u_D` 被量了。**
两档给不出观察阶 ⇒ 给不出 GCI ⇒ `u_num` 在 D 类里**根本没有定义**。

★ 而**代价几乎为零**：`cases/meshes/naca0012_2.5d/xcoarse.msh` 是**已提交的**，
`onera_m6/xcoarse_ss.msh` 也在；三分判定的机器（`yes/no/unstable`）**已经写好了**，
只是装在参照侧。⇒ 建议 2 = **把已经造好的仪器转过来对准自己。**

★★ 预告一个大概率结果，事前写下来免得被当成缺陷：跨声速量上我方多半会读到
`unstable`（§8.2 在参照侧就是 41/131 翻转）。**那正是想要的答案** ——
"我方在这个量上的数值不确定度 UNDEFINED"是一句真话，比一个不写误差棒的单点强。

## 6. 洞三 ★★★：**α = 0 跨声速非唯一性 —— 实测**

### 6.1 ★★★ 先更正一件事：**这个风险项目早就登记过，我一开始以为是新发现**

`docs/design.md` 里已经写着，而且写了两处：

- **§2「What FP cannot do」**：*"known non-uniqueness of FP solutions for airfoils in
  a narrow band around **M∞ ≈ 0.82–0.85 at low lift** (Steinhoff–Jameson). These are
  accepted model limitations, documented in §12, **not implementation targets**."*
- **§12 risk 2**：*"**FP non-uniqueness** (M∞ ≈ 0.82–0.85, low α)：continuation
  direction can select different branches. **Document; always ramp Mach upward from a
  subcritical converged state.**"*
- 而且 `track_p.md` 的 **G10.3** 还**预注册过一个 (B) 类判据** ——
  "WRONG-branch convergence：干净收敛但落在锁之外 ⇒ 尾迹坡道确实在做分支选择"。

⇒ **所以本节的贡献不是"发现了一个未知风险"**，而是三件更具体的事：

| | |
|---|---|
| **① 它在包线里，而门停在它前面** | CLAUDE.md 声明的目标是 **M∞ 0.3–0.87**，design.md 记的带是 **0.82–0.85** ⇒ **声明包线包含已登记的非唯一带**。而 D05 的 α = 0 腿只到 **M 0.75** —— **门恰好停在风险开始的地方。** |
| **② 登记的缓解措施没有被强制，也没有被门检查** | §12 说 "always ramp Mach upward from a subcritical converged state"。实测：`solve_newton_lifting` **接受任意 M∞ 的冷启动**，而 **D05 / D11 / D12 正是冷启动**跑 M 0.778 / 0.80 / 0.803 的。**没有任何代码或门执行这条缓解措施。** |
| **③ "文档化"这一条也没兑现到运行时** | §12 risk 3 的缓解措施逐字是 *"warn at runtime when max(M) exceeds 1.35"*。实测 **未实现**：全库唯一的运行时警告是 `newton.py:1577` 的 sigma-freeze 一条；`1.35` 只出现在 `entropy.py` 的一段推导注释里。 |

★★ 而**测量还给出了一件 §12 的措辞没有覆盖的事**：坡道**不是**一个可靠的分支选择器。
见 §6.2 —— coarse M 0.86 上冷启动与向上坡道**各自收敛到不同的分支**；
medium M 0.86 上**坡道那一臂反而不收敛且开始钳制**（505/319），冷启动那一臂收敛。
⇒ "always ramp upward" 是一条**未经检验的缓解措施**，而它是目前唯一登记在案的防线。

**文献锚**（design.md §12 引的就是第一条）：Steinhoff & Jameson AIAA-81-1019 /
*AIAA J.* 20(11) 1982；Salas, Jameson & Melnik NASA TP-2385 (1985) 进一步把它归因于
**保守位势模型对激波的近似处理**，而不是物理 —— 这一条对本项目有直接含义：
**熵修正正是一处"对激波的近似处理"**，所以它是不是杠杆是个可测的问题（§6.3 测了，答案是"不登记方向"）。

### 6.2 实测（`bench/studies/gate_audit_20260905/`，52 行 CSV）

固定 M∞ = 0.86、固定 8 线程、熵修正 ON。**唯一变化的是 `n_picard_seed`，
它只改初值。**

**coarse（n = 6106）：**

| `n_picard_seed` | cl | cd_p | Δx（上−下激波） | 收敛 | \|R\| | lim/flr |
|---|---|---|---|---|---|---|
| 0 | **+0.201727** | 0.03531 | +0.1934 | ✓ | 4.6e-13 | 0/0 |
| 2 | **+0.435982** | 0.04391 | +0.1481 | ✓ | 2.8e-13 | 0/0 |
| 5（生产值） | **+0.061464** | 0.03374 | +0.0595 | ✓ | 4.0e-13 | 0/0 |
| 8 | **−0.005919** | 0.03320 | +0.0017 | ✓ | 3.3e-13 | 0/0 |
| 12 | −0.086925 | 0.05858 | +0.0033 | ✗ | 1.2e-07 | 0/0 |

⇒ **四条完全收敛、零钳制的腿给出四个不同的解**：cl 跨越
**−0.005919 … +0.435982（span 0.4419）**，cd_p 跨越 0.0332…0.0439（**32 %**），

### 6.4 ★★ 一个顺带的机制候选：`classify_failure` 可能缺第六种模式

上表里 medium 在 **M 0.83 / 0.84 / 0.85 三档全部不收敛，而 `n_limited = n_floored = 0`**
（|R| 停在 1e-7…1e-6），两侧到了 0.86 又收敛。**这正是分岔点邻域该有的样子**：
在转折点上 Jacobian 趋于奇异，Newton 既不钳制也不发散，就是停住。

现有五种模式（钳制 / 极限环 / 病态 / 线搜索坍缩 / σ-输运）会把它归进"极限环"，
而处置方式完全不同：极限环要修冻结选择的抖动，**近分岔的病态要么缩包线、要么换
激波处理，调求解器没有用**。

⇒ **候选，不是结论。决定性检验很便宜**：沿这条 Mach 扫描记 J 的最小奇异值 /
条件数，看它是否在 0.83–0.85 上塌下去再回来。**本轮没有做。**

### 6.5 这为什么是**审计级**的发现，而不是一条趣闻

- ★★★ **判据已经存在、形状已经对了，只是工况点没到。**
  D05 的 `test_zero_incidence_carries_no_lift` 断言 `|cl| ≤ 0.005`。
  把同一条判据往上延伸：**medium / M 0.82（收敛、零钳制）|cl| = 0.0234 = 4.7×
  阈值 ⇒ 今天就是红的**；M 0.86 是 **104×**。
  ⇒ **G-TEETH 由构造满足** —— 不需要设计新判据，只需要补工况点。
- **所有可用性仪表都报"好"**：converged、|R| ~ 1e-13、`n_limited = 0`、
  `n_floored = 0`。GS1.4 的"钳制不静默"合约**在原理上看不见这一类**。
  这是能力边界文书里"anomaly 1"、以及 `bench/usability.py` 存在理由的**活实例** ——
  而且比 `upwind_c = 1.10` 那个实例更硬：那里候选集有共识，这里**候选集没有共识**
  （coarse 四条收敛腿 cl ∈ {+0.202, +0.436, +0.061, −0.006}），
  **中位数共识法在这里会挑出一个任意支并宣布它正常**。
- **它给几处分别归因过的现象提供了一个统一的候选机制**（**候选，不是结论**）：
  M1a 的"soft shift"（冷 seed-0 腿零钳制却把 cl 从 0.254830 挪到 0.252930 并翻了
  一个判据的符号）、M1c 的种子敏感度、Track V 记的"medium 不动点散射"、
  以及 §6.4 那三档不收敛。**决定性检验就是 §6.2 那张表的形状**：固定一切、只改初值。
  ★ 但要注意口径：M1a 在 **M 0.80 / α 1.25**，本轮测的是 **α = 0**；
  ⇒ 这是**一个待检的假设，不是一条已建立的联系**。
- **它是"递进"的反例**：C 类每一级都干净（C08 Ringleb 有超声速区但**没有激波**），
  D 类比的是升力工况；**没有任何一级会去问"这个离散问题的解唯一吗"**。

### 6.6 ★ 边界，明写

- 只有 **coarse M 0.86** 给出了"≥2 条完全收敛、零钳制的腿"这一最强形式；
  medium 在 M 0.86 上只有 **1 条**完全收敛（seed 5），其余停在 |R| 1e-7…1e-1。
  ⇒ **medium 上我不说"多解"，只说"一个收敛的、零钳制的、cl = −0.52 的零迎角解"**
  —— 那一句本身就够了。
- 未收敛的腿 `n_limited = n_floored = 0`（seed 8/12 那两条 medium 例外，见 CSV），
  **但本轮没有读 `accept_reason`，所以我不给它们命名模式**（§6.4 的第六模式是候选）。
- 本轮**没有**在 α ≠ 0 上做同样的探针，也**没有**在 M6 三维上做。

## 7. 洞四：四处规模较小但确定的缺口

### 7.1 ★★ 阻力：**5 个门读它，0 个门断言它**

`cd` / `cd_pressure` 出现在 D05 D06 D07 D08 D10 的参考读取里，写进证据 CSV，
**没有一条 `assert` 碰它**。而其中**一条判据是免费的、精确的、且极其敏感**：

> **亚临界无粘解的压差阻力必须趋于零（d'Alembert）。**

D05 自己的 CSV 就有：M 0.50/α 2.0 的 `cd` = **4.97e-3（coarse）→ 1.56e-3（medium）**。
这是一个**纯误差范数**，不需要任何参考数据。收缩 **3.19×**，而这两档的
h 比（2-D 用 `h ~ N^(-1/2)`，节点 6106 → 21874）是 **1.89** ⇒ 隐含阶
**1.82** —— ★ 指数用错会把每个隐含阶都读错，这是 §8.1 那一轮
自己记下的坑。C03 球、C06 圆柱同理（精确值都是 0）。
⇒ **建议 4：把亚临界 cd 立成 C/D 两侧的误差范数门。**
★ 三维要注意 G-DOMAIN：M6 的压差阻力**包含真实的诱导阻力**，不趋于零 ——
那里的对照量是 Trefftz 面的 `cl²/(π·AR·e)`，是另一条门，别混。

### 7.2 ★★ 翼身构型：**没有任何外部参照**

`cases/reference_data/` 里**没有一个字节**与 wing-body 有关。E02 只断言自锚定数
（`cl_p 0.2738` ± rtol、0 钳制、M0.84 达到）。⇒ Track B 十几个阶段的主战场
（含最长的未解现象：结合部 pocket，B23–B29）**整体处在"X 类"**。
归类 note §6 计划里"加了 Euler 参照就把快层的 X 半升格 D"**只对 M6 机翼兑现了，
翼身没有**。

### 7.3 ★ 网格族单一，而**现成的对照组躺在仓库里没人用**

每一条求解门跑的都是 pyFP3D **自己的生成器**造的网格。而
`cases/meshes/naca0012_hex_2.5d/` 与 `cylinder_hex_2.5d/`（各三档，**已提交**，
结构化 O 型网格切成 tet）—— **没有任何门在上面求解**（`tests/A18` 只测生成器）。
⇒ 同一几何、两种拓扑的交叉检验**只差一个门**，而它直接攻击"生成器有系统缺陷时
所有门共享该缺陷"这一单点。

### 7.4 ★★ mesh manifest：**造出来是为了堵一个洞，而它没有消费者**

`pyfp3d/mesh/manifest.py` 是为"跨网格代"那次五天的债专门造的，20 份 manifest
已提交。**活的消费者只有 `bench/stamp_mesh_axes.py` 一个，而 `bench/` 不在任何
测试收集里** ⇒ **G-CADENCE 不满足**。`tests/F/test_F01` 只测 manifest 的机器
（路径命名、extra 字段、缺失返回 None），**不比对任何一张真实网格**。

而风险是集中的：M6 / 翼身那一族 `.msh` 是 **gitignored + 随手重生成**的，
D04 D07 E01 E02 全读它们；2-D 那一族是**已提交**的，没有这个风险。
⇒ **建议 5**：一条 session 级 fixture，读盘网格时校验
`read_manifest(p)["sha256"] == mesh_fingerprint(p)["sha256"]`，不符就**红**。
一行判据，覆盖本项目自己记过的最贵的一次误比较。

### 7.5 ★ 一处文档与实现不符：`tests/D` 的周期

CLAUDE.md 写 **"`tests/D`（门控全集，相位边界）"**，实测 **13 个 D 文件里只有 2 个
（D03 / D04）带 `PYFP3D_TRANSONIC_GATES`** ⇒ D05–D13 跑在**默认周期**上。
这未必是错的（可能是有意的改动），但**两边现在说的不是一回事**，
按本项目的规矩要么改文档跟实现、要么反过来，并写明是哪一种。

## 8. 实测二：网格实现噪声 —— 兼记一处**被我自己的测量否掉的假设**

**我先提出的假设**：C06 在 medium 上残留的 ~1.1 % cl 误差是 `r_far = 15` 的远场截断
（对 Γ = 1.2 的环量，r = 15 处涡诱导速度 Γ/2πr ≈ 1.3 % U∞ —— 数量级对得很像）。

**测量否掉了它。** 固定 h、扫 `r_far ∈ [20, 55]`（这个范围内远场早已收敛，`r_far`
是**惰性旋钮**，它唯一改变的是 gmsh 返回哪一张三角剖分）：

| h_wall | cl_rel 范围 | 极差 | std |
|---|---|---|---|
| 0.04（coarse） | **1.8080 – 3.9011 %** | **2.09 pp** | 0.77 pp |
| 0.02（medium） | **0.8822 – 0.9829 %** | **0.10 pp** | 0.036 pp |

⇒ 远场不是限制项（medium 上扫 6 倍域大小只动 0.1 pp，且**非单调**）。
**`farfield_dirichlet` 的涡修正按它 docstring 承诺的那样工作。**

★★ **但探针量到了另一件更要紧的事**：**coarse 档的误差主要由"抽到哪张网格"决定，
不是由 h 决定。** 后果直接落在一条现有判据上 ——

> C06 的 `test_lift_error_contracts_with_refinement` 要求 `coarse/medium ≥ 2.0`，
> 注释记"实测 3.477 / 1.136 = **3.06**，余量 53 %"。
> 而 coarse 在 [1.81, 3.90] 之间抽 ⇒ **该比值的取值范围是 [1.90, 4.10]**，
> **跨过阈值**。所谓 53 % 余量，**小于它自己输入量的未测噪声。**

★ 口径说清楚：门里 `r_far` 是固定的 15，所以门本身是确定性的；我用 `r_far` 的惰性
扫描**作为重剖分的代理**。真正的风险面是**任何一次重剖分**：gmsh 在
`environment.yml` 里只写了 `>=4.11`（未钉版本），M6 那一族又是随手重生成的。

⇒ **建议 8**：给每条对着阈值的比值/阶判据，量一次**网格实现噪声**，
并把阈值定在噪声之外；这正是"参照物的分辨率是逐例的性质"那条纪律的**镜像**——
**被测物的分辨率也是逐例的性质。**

## 9. 递进性：一条 **debug 二分阶梯**（本 note 对后续调试的主要交付）

现有门是一张**覆盖表**，不是一张**定位表**。下表把它重排成"症状 → 依次问哪一级"，
每一级都**只加一个新机制**，所以第一条红的那一级就是嫌疑段。

| # | 这一级新加的机制 | 门 | 真值? | 走生产 Newton? | 现状读数 |
|---|---|---|---|---|---|
| 0 | 装配 / 梯度 / 度量 | A01–A11 | 恒等式 | — | 绿 |
| 1 | 不可压场 + 曲壁 | C01 MMS · C03 球 | ✓ 精确 | ✗ | 阶 ≥1.9；球 = P1 固有极限（G1.6） |
| 2 | **升力（给定 Γ）** + 压力积分 | **C06** | ✓ 精确 | ✗ | medium cl **1.14 %** |
| 3 | **Kutta 自己选 Γ** | **C07 KT** | ✓ 精确 | ✗ | medium Γ **2.80 %** / cl **3.04 %** |
| 4 | 可压放大 | C09 PG | 渐近 | ✗ | < 2 % |
| 5 | **超声速区 + 人工耗散** | **C08 Ringleb** | ✓ 精确 | ★ **✗ DuctSystem** | sup 区 RMS **0.100** |
| 6 | **激波** | **C05 喷管** | ✓ 精确 | ★ **✗ DuctSystem** | 位置误差 < 1 单元 |
| — | ★★★ **断档：对真值 + 走生产驱动器** | **无** | — | — | **洞一** |
| 7 | 生产驱动器 + 外部数值参照（2-D） | D05 / D06 | code-to-code | ✓ | 亚临界 0.05 %；M1 靶 −1.98 % |
| 8 | 三维 + 尾迹片 + 展向 | D07（+3D-2） | code-to-code | ✓ | 激波可设门；**cl 发散 −6.1 → −9.2 %** |
| 9 | 粘性耦合 | D13 / D08 / D09 / D10 | XFOIL / RANS 带 | ✓ | 2-D 可比；**3-D 与 RAE 是能力边界** |
| 10 | 对实验 | D11 / D12 / D04 | 实验 | ✓ | 只记录偏置（裁决三） |

**读法**：
- 第 2 级红 ⇒ 壁面恢复 / 压力积分，**与 Kutta 无关**（C06 给定 Γ 跳过 Kutta 环）。
- 第 2 绿、第 3 红 ⇒ **Kutta 估计器**（这正是 P14 当年靠换估计器解决的那一段）。
- 第 5 绿、第 6 红 ⇒ 激波捕捉 / 熵修正，而**不是**人工耗散标定。
- 第 7 红而 1–6 全绿 ⇒ **嫌疑落在断档里**：生产驱动器的全局化 / 钳制 / 种子 /
  冻结策略，**目前没有任何一级对真值检验过它们**。这就是建议 1 的价值。
- **答案随初值/线程/重剖分变**（不是"错"，是"不唯一"）⇒ §6 的探针；
  **现有阶梯里没有这一格**。

★★ 还要记一条**已经量到、但没被用起来**的读数：**C08 的剂量响应说明生产的耗散
标定不在精度最优侧** —— 同一张网格上 `upwind_c` 1.5 → 0.25 把超声速区 RMS 从
**0.1001** 压到 **0.0376**（2.66×），而 `m_crit` 1.20 压到 **0.0293**（3.4×）且仍
37 步收敛。C08 已经把这个事实**锁**成断言了（`test_m_crit_is_the_cheaper_lever`），
但没有下一步。它与 D05/D06/D07 的激波位置偏差**是同一根杠杆**，
应当放在一起读（注意 §4 的跨配置口径：C08 那几条腿熵修正是关的）。

## 11. 我这一轮的错误，与被测量否掉的假设

按本仓库的规矩明写，因为它们比结论便宜、但比结论更容易复发：

1. ★★ **"远场截断限制了 C06"** —— **被自己的探针否掉**（§8）。数量级估计
   （Γ/2πr ≈ 1.3 % ≈ 实测的 1.1 %）**对得严丝合缝，而它是巧合**。
   ⇒ 数量级吻合不是证据；探针只花了 30 秒。
2. ★★ **"Newton 路径的远场涡用了 β = 1.0（不可压），是个 bug"** —— 我在
   `newton.py:289` 看到 `beta=1.0` 就这么读了。**读上下文之后是错的**：那一次调用
   只用来定 **Dirichlet 节点图样**（注释明说图样与 β 无关），真正的值走
   `set_mach()`，那里 β 是对的。⇒ **一行代码不是一个语义**。
3. ★★★ **"α = 0 非唯一性是一个新发现"** —— **不是**。`design.md` **§2 与 §12 risk 2
   都写着它**，连 Steinhoff–Jameson 的引用都在参考文献里，`track_p.md` 的 G10.3 还
   预注册过一个 (B) 类"错分支"判据。我是在查 G10.1（非升力 Newton 入口，洞一的修法）
   时顺着 `track_p.md:1171` 的 "known FP hazard" 一句才翻到的。
   ⇒ **在把一件事称为发现之前，先 grep 自己项目的设计文档。**
   本节因此被重写：贡献从"发现风险"改成"**它在包线里 / 缓解措施未强制 / 未实现 /
   无门**，而且现在有实测"（§6.1）。★ 这条对读者的用处比结论大：
   **本仓库的风险登记与门之间没有任何机械联系** —— design.md §12 列了 5 条风险，
   没有一条能机械地查到"哪道门在守它"。
4. ★★★ **"熵修正把非唯一性的起始 M∞ 往下推"** —— 我**已经把这个方向写进初稿了**，
   依据是 coarse M0.86 与 medium M0.83 两格。**把完整 CSV 拉出来对照，两个档方向
   相反**（coarse 上 OFF 在 0.83/0.84 更差、ON 在 0.86 更差；medium 上 ON 更早破）
   ⇒ **改成"不登记方向"**（§6.3）。这与 D05 处理"全速势激波该在 Euler 下游"那条
   预期是同一条纪律 —— **两格不是一张表**。
5. ★ **"6 个 `pyfp3d` 模块没有任何测试引用"** —— 我的正则只匹配
   `from pyfp3d.x.y import`，漏了 `from pyfp3d.x import y` 这一种写法。逐个 grep 后
   **6 个里 5 个是假阳性**。⇒ 与归类 note §2 栽的是同一跤（`solve_*` 字面 grep 看不见
   helper 里的求解）；**这次我在写下之前查了**。

6. ★★ **"medium 在 M0.86 上也有两条干净的分支"** —— 我第一次的临时脚本上确实两条
   都收敛，但那条 ramp 链走的 Mach 序列与最终提交的探针**不同**
   （少了 0.82 / 0.84 两级），换了链就换了初值，答案跟着变。
   **committed CSV 里 medium 只有一条完全收敛的腿** ⇒ §6.2 已改成"medium 不说多解"。
   ★ 这本身就是同一个现象的第三次出现，但**我差点把一个未提交的读数写进结论** ——
   纪律 3 的反面教材。

★★ 还有一条**不是错误、但必须标注的口径**：§6 的表里有若干腿 `converged = 0`。
除 medium seed 8 / 12 两条外它们都 `n_limited = n_floored = 0`，所以**不是钳制模式**；
但本轮**没有读 `accept_reason`**，所以**我不给它们命名模式**（§6.4 的"第六模式"
是候选，不是结论）。§6 的**多解**结论只建立在 **coarse 那四条**收敛腿上。
