## 2. ★★ 判据的形状要跟着参考的形状走

D08/D10 的参考**每工况有 SST + SA 两个湍流模型** ⇒ 它是一条**带**而不是一个点。
所以判据形状是**落在带内**，不是"与某个模型差 X %"—— 后者要**武断地挑一个
湍流模型当真值**。这正是数据请求当初写"同工况至少两个湍流模型，
分歧 = 这道门的分辨底噪"的用意。

实测（NACA0012，trip 匹配的两条）：

| 工况 | coarse | medium | RANS 带 | 带宽 |
|---|---|---|---|---|
| M0.50/α2.0 trip 0.05 | +7.2 % | **+10.2 %** | [0.2500, 0.2569] | 2.7 % |
| M0.50/α2.0 trip 0.30 | **−1.9 %** | **+6.1 %** | [0.2612, 0.2658] | 1.8 % |

**两条腿都在加密时向上跑**，trip 0.30 还从带下穿到带上 —— 与 D13 记录的
"cl 离 XFOIL 从 +2.3 % 走到 +5.6 %"同一签名（那一轮把根因指到湍流闭合的 H 族）。
目前没有一条落在带内，**带内包含设为将来的判据**。

★ M6 的带是 **3.07 %**，而参考自身的网格差是 **0.35 %** ⇒ **9.5 倍**。
将来 D10 设门时，主导不确定度是**湍流模型**而不是网格。

## 3. ★★ 参照物的分辨率是**逐例**的性质

同一条判据 ——「pyFP3D 与 CFL3D 的差 vs CFL3D 自身的 L2→L3 差」——
在两个翼型上给出**相反**的结论：

| 算例 | 差 | 参考自身不确定度 | 比值 | 判定 |
|---|---|---|---|---|
| NACA M0.75 激波 | 0.0047 | **0.018**（且**非单调** 0.285→0.278→0.296）| **0.26×** | **不可分辨** |
| RAE M0.725 激波 | 0.0309 | **0.00088** | **35×** | 可分辨 |

两道门里各锁一条**镜像断言**：D05 锁"它现在不可分辨"（参考收紧到能分辨时会红，
那时才写真正的激波判据），D06 锁"它现在可分辨"（参考放松时会红）。

★ 这与 D07 对实验那次是同一条：M6 实验采样 0.040–0.050 c，使 **5/7** 站位的
激波位移不可分辨。**判据不能把一个量与一个自身分辨率比该差值更粗的参照物相比。**

## 6. 两条能力边界，门锁的是**失败的形状**

### 6.1 D09 —— RAE2822 耦合环在第 **0** 次外迭代死

`SystemError: CPUDispatcher` 只是 numba 遇 NaN 的**症状**；根因是
`mach_squared_field` 返回**负值**：

| | RAE2822（有弯度）| NACA0012（对称，**同一套机制**）|
|---|---|---|
| M² < 0 站位 | **9 / 206** | **0 / 206** |
| min M² | −63.90 | — |
| max q² | **23.60**（\|u_e\| 4.86 倍来流）| **1.98** |
| 位置 | x/c 0.227–0.287 与 0.744–0.764，**全在上表面** | — |

★ 那条**判别项**（对称翼型干净）是关键：没有它，这只能说成"IBL 一概不能用"。
★★ **定位到，但不归因**：D06 证明**同一张网格**的无粘解是健康的
（收敛，cl 0.914939，激波 0.6049）⇒ 问题在**站位边缘速度提取**，不在 FP 解。

★★★ **一个被自己的检查否掉的假设，写进了门里免得有人重走。**
我先怀疑是 D12 那族的分侧错误 —— `coupling.py:334` 确实仍用**全局 y 基准**
（`ysum/ycnt >= y_stag`），而 D12 已把 `section_cut.py` 的同族规则换成
**局部外法向**，**没有回移**（纪律 #9）。**证伪**：那 9 个点的 y 是
+0.054…+0.059（x/c 0.25）和 +0.040…+0.042（x/c 0.75），**正是 RAE2822 上表面
该有的位置**；而"一个站位的节点全在一侧"在**对称的 NACA0012 上同样是 101/102**，
是正常结构不是缺陷。**分侧是对的。**

## 8. 2-D 参考数据集补第四档 —— 而结果不是"补齐"，是"定不了"

第 7 节欠账 #3（2-D 没有渐近检验）的执行。分两步。

### 8.1 先加检验，三档上就已经很难看

给四个 2-D 数据集加 `ratio` / `implied_order` / `asymptotic`（**2-D 用
`h ~ N^(-1/2)`，不是三维的 `N^(-1/3)`；用错指数会把每个隐含阶都读错**）。
这条阶梯 r = 1.4034 / 1.4166、比值之比 0.9907（近乎均匀）⇒ p=2 应给 **0.518**、
p=1 给 **0.729**，所以 "ratio < 1" 本身就是**未标定**的。

三档实测：**131 个量里 20 个不渐近**，却都带着 `delta_L2_L3` 当误差棒。
最刺眼的是 `rans_rae2822` M0.730 的 `cd_pressure`（ratio **37.0**）和
`x_shock_upper`（**43.8**）。另有 **6 个 ratio < 0.2**，正是 D07 第四档
证明为偶然穿越的签名。

★ 原 docstring 说过"三档定不了阶"，那是**刻意的选择、并没有错**。D07 给出的
是更尖锐的理由：**不是"定不了阶"，而是一个量可能根本没在收敛、却照样发布
一个看起来很小的最后差**。

### 8.2 ★★★ 加第四档：41 / 131 个判定翻转，而且双向

22 条 L4 腿（Euler 8 + RANS 14），求解墙钟 **2546 s**；L4 各方向续 √2 且全部
满足 mesh sequencing 的 4m+1（`n_foil 281 / n_wake 113 / n_grow 137`，
RANS `n_grow 225`，y+ 仍钉在 1）。

| | 三档 | **四档** |
|---|---|---|
| 误差棒确立 | 93 | **75** |
| 确实发散 | 20 | **3** |
| **加一档就翻** | — | **41** |
| 未定义（分母为零）| 12 | 12 |

**24 个 PASS→FAIL、17 个 FAIL→PASS。** 六个"可疑"里**三个确实是偶然穿越**
（0.083 → 1.822、0.049 → 7.988、0.044 → 9.187）。

★★★ **所以收获不是"现在判定对了"，而是"对三分之一的量这条阶梯无法决定，
而三档表此前在静默地给出两个可能答案中的一个"。** 判定改为**三分**：
`yes` / `no` / **`unstable (the two triples disagree)`**，后者 `error_bar` 写明
"一个三元组给 X、另一个给 Y，多一档就翻"。

★★ **一个被自己的检查否掉的解释**：我先怀疑翻转是"两个极小数之比由噪声主导"。
**证伪** —— 翻转组与稳定组的差值量级基本相同（|Δ_finest|/|值| 中位数
3.4e-03 vs 4.6e-03），且在 1e-5..1e-3 与 >1e-3 两桶里翻转率都是 **34–35 %**。
不是噪声地板效应。已写进代码注释。

### 8.3 由此改动的三道门

参考档从 L3 换到 **L4**，不确定度从**单一的最后差**换成**各档散布（极差）** ——
对一个判定不稳的量，最后一步的差可能恰好很小而它仍在游走，**游走的范围才是
不确定度**，且无论收敛与否都有定义。

* **D06 的数字要更正**：原按单一 delta 0.00088 说"可分辨 **35×**"；
  按四档散布 0.003169 是 **9.8×** —— **结论不变，倍数缩水四倍**。
  单一的最后差把参照物说得比它实际更精确。
* **D05** 的 0.0047 / 0.021941 = **0.21×**，仍不可分辨，理由更硬：参照物本身
  在 **0.022 弦长**的范围里游走（0.28502 / 0.27776 / 0.29578 / 0.29970，非单调）。
* **D08** 的 `xtr030` SA 带边判定 `unstable`（1.434 → 0.002）。
* ★ 四个真正设门的 cl **两个三元组都判 `yes`** ⇒ 设门部分建立在确立了的误差棒上。

★★ **一处会静默出错的漏改**：把参考档换到 L4 时力系数改了，**Cp 读取有四处
仍指着 L3** —— 那会造成"力系数比 L4、Cp 比 L3"的跨档比较，**不报错**。
靠 `grep '"L3"'` 逐处过才发现：**记得的地方和全部地方不是一回事。**

### 8.4 两处顺带修掉的东西

1. **`wall_s` 全是 0.0**，机制不是"从没记录"而是 `run_one` 的缓存分支写
   `wall_s=0.0`，于是**每次 `--derive-only` 重导都把这一列抹成 0**；更糟的是
   混用（缓存行 0.0、实跑行真实秒数）。**一个表示"没测"的 0 是谎**，改为留空。
2. **网格尺度从 `forces.csv` 的 `nj/nk` 读**，不再硬编码 `_GC_N` —— 硬编码的
   元组**加一档就静默失配**，而用失配的 h 算出的每个隐含阶都是错的。

★ 流程隐患记一条：L4 那次运行**在我改导出逻辑之前就导入了模块**，于是它用旧代码
写了三档表，必须重导。**在正在运行的作业所依赖的模块上编辑，会让那次运行用旧代码
完成** —— 这次代价只是重导（秒级）。
