## 1. ★★★ 本阶段的中心风险，先写下来：**写出一条不会失败的门**

这不是抽象顾虑，它是本项目**反复付过学费**的那一件事。一个"建立门"的阶段，
最可能的失败模式是**产出一批看起来完整、而实际上永远绿的门**。已测的先例：

| 先例 | 门 / 锁存在，而且是绿的 | 它看不见什么 |
|---|---|---|
| **`MACH_NOT_ATTAINED`** | `bench/run_capability_matrix.py` 的守卫比较 `abs(m_att − m)`，而 `m_att` **恒等于** `m` | ★★★ **一条在数学上不可能触发的守卫** —— 而它自己的注释说它存在是为了"不信任 driver 的标志位" |
| **湍流锁（48 条）** | 全部开窗在 `Re_θ ≥ 800` | 一次让 `c_f` 动 **4.5 %** 的改动 —— **它作用在窗口以下** |
| **求积 24 → 96 点** | 整套套件全绿 | 闭合输出动 **5.2e-03** |
| **求积 8 → 24 点** | Track V 一条锁都没红 | 30 个输出里 **9 个**动 > 1e-9，`θ*_1` 达 **6.46e-04** —— 它们的带**比这个量宽** |
| **B28 退役的前提** | 被重新阈值化后塞回一个**门控**测试 | 红了 **17 天**没人看见 |
| **`SHOCK_REF = 0.61, 0.02`** | 流传 **九份文档** | **任何参照文件里都不存在** |

⇒ 三条**常设要求**，从第一轮起对本阶段自己生效：

- ★★★ **G-TEETH：本阶段写下的每一条门，必须实测它在被保护的东西坏掉时会红。**
  做法是临时把被保护的量改坏（phase 4 的做法：`ETA_TURB = 40`），确认红，再改回。
  **一条没有被验证过会红的门，本阶段不算交付。**
- ★★ **G-DOMAIN：注册一条门时，必须写出"相反的结果会落在哪里"**，以及
  **它的窗口是否覆盖了它所声称保护的量的定义域**。这是本季四轮四个判据缺陷的共同句子
  （见 CLAUDE.md 的四问 + 第五问）。
- ★ **G-CADENCE：一条门必须说明它在哪个周期上跑。**`bench/` 不在任何测试收集里
  ⇒ 只活在 `bench/` 的门 = 不在任何周期上。三层是：未门控套件（~717 s）/
  快层（~740 s，每次收口）/ 门控全集（1:44:32 @8t，相位边界）。

## 6. 本阶段**成功的定义**，事前写死

★★ 一个"梳理"阶段最容易的自我欺骗是**把读过的东西当成做过的东西**。所以：

| | 算交付 | **不算**交付 |
|---|---|---|
| 门 | 一条门 + **G-TEETH 实测它会红** + 它跑在哪一层 | 一份"应该加门的地方"的清单 |
| 代码 | 删掉的死代码，或**记录为活的**并说明谁读它 | "看起来没用" |
| 文档 | 一条**可检查的**陈述变成断言，或明确记为不可检查 | 把过期的数字改成新数字（下次还会过期） |
| 算例 | 分类落定 + 死的连 knob 一起删 | 目录列表 |

★★★ **而 kill criterion 也事前写死**：如果某一轮发现**它要建的门在当前离散/仪器上
不可能有牙**（例如墙钟类），**判 RECORDED 并说明为什么不可门**，
**不许降低门的要求去换一个绿**。本项目历史上只放松过一次目标数字，
而那是一次**署名的使用者裁决**，不是一轮测量的产物。
