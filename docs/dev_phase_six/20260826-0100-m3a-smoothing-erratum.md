## 3 单变量 A/B：一次求解、两次提取

平滑只作用在**后处理**，所以正确的 A/B 不是跑两遍求解（那样 taper、线程、收敛路径都会一起动），
而是 **解一次、用同一个 φ 提取两次**。
**证据（已提交）：`bench/gate_results/m3a_smoothing_ab.csv`** —— 4 行 = 2 次求解 × 2 次提取：

| taper | smooth | pooled_rms_5 | band_LE_upper | band_MID_upper |
|---|---|---|---|---|
| True（生产） | 0 | 0.125974 | 0.242226 | 0.100636 |
| True（生产） | **1** | **0.120924** | **0.217125** | 0.100196 |
| False | 0 | 0.152328 | 0.256989 | 0.169417 |
| False | 1 | 0.147622 | 0.230235 | 0.168491 |

**溯源确认**：`taper=True, smooth=0` 的 `band_LE_upper = 0.242226` 对上已提交的
`m3_budget_head_medium.csv` 的 **0.242221**（5 位小数）⇒ A/B 与被勘误的证据同溯源。
★ `pooled` 有 +0.40 % 差（0.125974 vs 0.125478）——**如实记，不追**：本轮 8 线程，
已提交行的线程数未记录，属跨溯源差异。

★ **`taper=False` 那条腿没收敛**（`conv=False`, |R| 9.2e-07, 491 s）⇒ 它的两个数只作 RECORDED，
**不得用来给 taper 归因**。

## 5 勘误范围（实测，不是推断）

### 5.1 会动的：`m3_budget_head_medium{,_seed5,_seed12}.csv` 的 **22 列**

全部经 `section_cp_curve`：`pooled_rms_5`、`allpoint_rms_5`、`band_*`(6)、`rms_eta*`(7)、`xshock_eta*`(7)。

移动量（medium，生产 taper，单变量）：

| 量 | smooth=0 | smooth=1 | 相对 |
|---|---|---|---|
| `pooled_rms_5` | 0.125974 | 0.120924 | **−4.01 %** |
| `band_LE_upper` | 0.242226 | 0.217125 | **−10.36 %** |
| `band_MID_upper` | 0.100636 | 0.100196 | −0.44 % |

分带**份额**（SS = RMS²·n 加权）：

| | LE 上 | MID 上 |
|---|---|---|
| 已提交（phase 3 第 16 轮） | 70.35 % | 21.05 % |
| 本轮复现 smooth=0 | 69.87 % | 21.90 % |
| **smooth=1** | **63.93 %** | **24.72 %** |

★★ **「LE 主导」这个结构性结论稳健**（69.9 % → 63.9 %，仍是首位带）；
**绝对占比 70.35 % 不稳健**，引用时必须带上平滑状态。

### 5.2 不会动的：**16 列**

`cl_p`、`cl_kj`、`p14_cl_*`、`converged`、`res_final`、`m1_max`、`sigma_min`、`n_shock_cells`、
`n_floored`、`transport_converged`、`r2_validity`、`wall_s` 等 —— 直接由 φ 积分或来自求解器诊断，
**不经截面提取**。

★★ 这正是使用者裁决的形状：**载荷（`cl_p`/`cl_kj`）不平滑，截面 Cp 才平滑** ⇒
一条已提交的升力数字**一个都没有被这次改动移动**。

### 5.3 不受影响的引用（查过，不是假设）

| 引用点 | 引的是什么 | 结论 |
|---|---|---|
| `pyfp3d/kernels/entropy.py:170` | `m3_budget.csv` 的 `m1_max`（求解器诊断） | ✗ 不动 |

⇒ 处置 = **在 `run_m3_budget.py` 的 `smooth_passes=1` 注释处写明**：这三个文件是**改动前**的读数，

改冻结的档案本身就是本项目记过的危险。

## 8 本轮的教训（都有测量支撑）

1. ★★★ **一个「重生成」如果没有改变目标文件的 mtime，它就没有发生。**
   查 `mtime` + `git status` 是零成本的，而我先花了一整轮去解释一组「+0.00 %」。
2. ★★ **事前预测的价值不在于对，而在于错了会**停。** 本轮预测的**数**对了（MID −0.44 %），
   **前提**错了（误差不在 MID 而在 LE），而只有停下来才看得见这个区别。
3. ★★ **后处理改动的 A/B 应当共用同一个解。** 重跑求解会把 taper、线程、收敛路径一起卷进来 ——
   本轮 no-taper 腿直接不收敛，正好演示了那条路会得到什么。
4. ★ **归因要留白。** −6.12 % 里有 −4.01 % 是测出来的，−2.19 % 不是；把后者也写上归因会是一次
   没有证据的推断。
5. ★ **一次改动要按列分范围**，不是按文件：同一个 CSV 里 22 列动、16 列不动，而不动的那 16 列
   恰好是所有升力数字。
