## 0. 一句话

`cfl3d.inp` 里 **`NITFO ≥ NCYC`**，于是 CFL3D 在最细网格上**整个求解过程都用一阶
空间精度**，而 deck 里明明写着 `RKAP0 = 0.3333`（κ=1/3 MUSCL）。M6 的 Euler 阶梯
（`nitfo 1000 / ncyc 1000`）和 M6 的 RANS 阶梯（`nitfo 1000 / ncyc 800`）**两条都
中了**；2-D 的四个数据集**没有中**（`NITFO` 0 / 500 / 1500 对 `NCYC` 1000 / 2000 /
2000，都会切换）。

## 1. 机理（读源码，非推测）

`cfl3d/libs/resid.F:141`

```fortran
if (icyc.ge.nitfo+1 .and. level.ge.lglobal) then
   rkap(1:3) = rkap0(1:3)      ! 请求的精度（κ=1/3）
else if (level.ge.lglobal) then
   rkap(1:3) = -3.             ! ★ 一阶
else
   rkap(1:3) = rkap0(1:3)      ! 多重网格的粗层
end if
```

`rkap = -3.` 是 CFL3D 的一阶标志。关键在 `icyc` 的作用域 ——
`cfl3d/dist/mgblk.F:416`：

```fortran
levt  = levelt(iseq)
nitfo = nitfo1(iseq)          ! ← 每个 mesh-sequence 层各自的 nitfo
ncyc  = ncyc1 (iseq)
...
do 7000 icyc=1,ncyc           ! ← icyc 在每层都从 1 重新开始
```

⇒ `icyc` **不是累计的**，它和本层自己的 `nitfo` 比。`ncyc = nitfo = 1000` 时
`icyc >= 1001` 永不成立，而 `level >= lglobal` 在最细全局网格上恒成立 ⇒ **最细网格
1000 步全部一阶**。粗层用的是 `rkap0`，但决定收敛解的是最细层的残差，所以那不救。

★ 日志末尾显示 `it = 3000`，是三层各 1000 步的**累计打印计数**，不是 `icyc`。我先前
把它当成了 `icyc` 的证据 —— 这正是这个缺陷能藏住的原因之一。

## 2. 为什么读 deck 抓不到

`.inp` 里两条阶梯都老老实实写着

```
   IFDS(I)   IFDS(J)   IFDS(K)  RKAP0(I)  RKAP0(J)  RKAP0(K)
         1         1         1    0.3333    0.3333    0.3333
```

**一个"请求的"参数不是"生效的"参数。** 这和本项目已记录的 "signature is not the
contract"、"a knob's name is not its scope" 是同一族。能抓住它的检查只有两种：

1. 读源码确认门槛（本轮做的）；
2. **行为检查** —— `nitfo < ncyc` 时残差历史必须在 `icyc = nitfo+1` 处出现可见断点
   （精度切换会激起残差跳跃）。若没有断点，切换就没发生。

⇒ 已在 `wing3d_otip.py::write_inp` 和 `cfl3d_runner.py` 的配方表加了 `nitfo < ncyc`
的硬断言（import 时即校验，四个用例逐一验证过：1000/1000 和 1000/800 必须 raise，
1000/2000 和 0/1000 必须通过）。

## 3. 是怎么被发现的 —— 值得记下来的路径

**不是**看着数字不对发现的，而是去给一个判据找参照时发现的。

用户批准加第四档后，第一件事是问"这条阶梯上，一个 p 阶收敛的量*应该*给出多大的
比值"。算下来：以 `h ~ N^(-1/3)`（总点数）为网格尺度，这条阶梯近乎均匀
（r = 1.376 / 1.340，比值之比 1.027），于是

| p | 预期比值 |
|---|---|
| 2.00 | 0.496 |
| 1.00 | 0.675 |
| 0.50 | 0.787 |
| 0.25 | 0.849 |

而实测：cd 比值 0.744 ⇒ **隐含阶数 p = 0.68**。一个请求了 κ=1/3 的格式，在光滑区
不该只有 0.68 阶。**是这个不一致把注意力引向"格式到底是几阶"**，而不是任何一个
"看起来不对"的数。

★★ 顺带暴露了我自己的判据缺陷：**"ratio < 1" 从来没有被标定过**。1.0 不是收敛量
给出的值，只是"差不再缩小"的分界。这条判据放过了 0.2 阶的量。已改为在表里同时报
**隐含阶数**，读者要把误差棒减半时能算出代价（p = 0.68 时需要点数增大 2.8 倍，
不是 1.4 倍）。这是相三那张"四个判据缺陷"表的"阈值无标定"形态。

## 5. 替代配方 —— 为什么不能简单把 nitfo 设 0

`nitfo` 的长一阶启动在这个算例上是**承重的**：已提交的收敛标定表里 CFL 1.0 和 0.8
都发散，只有 `CFL 0.2 / NITFO 1000` 这条到了 |R| 8e-11。所以修法是 **`ncyc > nitfo`**，
而"需要多长的一阶启动"是个待测量的问题，不是可以猜的。

L1 上三条腿（其余全同）：

| 腿 | nitfo / ncyc | 目的 |
|---|---|---|
| control | 1000 / 1000 | 复现已提交档位（应与 committed L1 一致） |
| long | 1000 / 2000 | 保住已验证的启动，之后 1000 步二阶 |
| short | 500 / 1500 | 启动减半，同样的二阶预算 |

`control` 这条腿同时是**仪器校验**：它必须复现 committed L1 的 cl 0.325440 /
cd 0.033666（原始 SREF=1 值）。如果不复现，问题就不只是 nitfo。

### 5.1 实测结果（2026-09-03，L1，4 线程/腿，load ~2）

| 腿 | nitfo/ncyc | wall | cl | cd | \|R\| | drop |
|---|---|---|---|---|---|---|
| control | 1000/1000 | 506.1 s | **+0.325440** | **0.033666** | 1.636e-10 | 3.87 |
| long | 1000/2000 | 1032.5 s | +0.342948 | 0.014291 | 2.163e-08 | 2.27 |
| short | 500/1500 | 821.1 s | +0.342949 | 0.014291 | 2.172e-08 | 2.27 |

三条结论，都是硬的：

1. ★★ **仪器校验通过** —— `control` 把 committed L1 复现到每一位（cl 0.325440 /
   cd 0.033666 / |R| 1.636e-10 / drop 3.87），所以已提交的那一档**确实就是**这个
   一阶解，缺陷定位无歧义。
2. ★★★ **二阶把答案挪动了很多**：cl **+5.38 %**，cd **−57.6 %**。cd 掉一半以上是
   一阶数值耗散的签名 —— 一阶格式引入伪熵、伪阻力。⇒ 已发表的 D07 阻力**高了一倍多**。
3. ★★ **一阶启动的长度不影响答案**：`long` 与 `short` 的 cl 差 1e-6 相对、cd 完全
   相同、|R| 差 0.4 %。⇒ 500 步启动够用，`short` 便宜 20 %。**配方 = nitfo 500 /
   ncyc 1500，由测量定，不是猜的。**

二阶腿的残差落在 |R| 2.2e-08 / 2.27 decades，高于一阶腿的 1.6e-10 / 3.87 —— 符合预期
（更高阶的残差更难压，激波限制器造成平台），且仍在 ≥ 2 decades 的可用范围；四档
阶梯的残差口径会逐档记录。

### 5.2 行为检查：精度切换确实发生了（独立于源码阅读）

`order_switch_check.py`：切换空间算子会扰动解，所以残差历史必须在
`icyc = nitfo+1` 处出现可见断点。实测（相邻步 |Δlog10 R| 对中位数的倍数）：

| 腿 | 断点位置 | 幅度 | 判定 |
|---|---|---|---|
| long | icyc **1001** = nitfo+1 | **1049×** 中位数 | 切换发生 ✓ |
| short | icyc **501** = nitfo+1 | **602×** 中位数 | 切换发生 ✓ |
| control | 最大跳变在 icyc 1000 = **最后一步** | 828× | 无切换（是末尾多余行的伪迹）✓ |

★★★ **这个检查自己先出过两次错，而且第二次是"自信地报了错误结论"**，值得记下：

1. 第一版把第 1 列当成迭代数 —— 实际列布局是 `LV BLK IT res Tres Cl Cd Cdp Cdf`，
   第 1 列是 **mesh-sequence 层号**。于是 `it.max()` = 3，窗口选中了全部行，
   它报出 **"switch did NOT fire"** —— 而同一批腿的答案已经动了 5.4 % / 57.6 %。
   **一个坏了的仪器给出自信的判定，比直接报错更糟。** 我没有采信它，因为它和一个
   强得多的测量矛盾 —— 这正是"别把工具的结果照单全收"该起作用的地方。
2. 第二版修对了列，但假设 `IT` 每层重置。实际 `IT` 是**累计**的，而 Fortran 的
   `icyc` 每层重置（mgblk.F:416）—— 两个计数器同名不同义。修正是
   `icyc = IT − (nlv−1)·ncyc`。**发现它的线索是：最大跳变落在 3501 和 5001，
   恰好等于"第三层起点 + nitfo+1"** —— 数据自己指出了偏移量。

★ 附带确认了用户提示的那个遗留问题：`control` 的最细层有 **1012** 行而 `ncyc = 1000`，
多出的 12 行就是末尾多余输出；`control` 的最大跳变正落在最后一步上。**这也是不能靠
行位置取力系数的又一个证据**（力系数已改从 `cfl3d.out` 的 SUMMARY 取）。

## 7. 教训（按可复用性排序）

1. ★★★ **一个"请求的"参数不是"生效的"参数。** 要么读源码确认门槛，要么写一个
   **行为检查**去看它是否真的生效。本项目已经栽在同一族上多次：签名不是契约、
   旋钮的名字不是它的作用域、F06 的 "reads the CSV" 其实是字面量对字面量。
2. ★★★ **判据必须先标定，再使用。** "ratio < 1" 里的 1.0 是个圆整的数，不是任何
   收敛量给出的值。要问的是"这条阶梯上 p 阶应该给多少"。**去给判据找参照的那一步，
   本身就是发现缺陷的手段** —— 本轮就是这么发现的。
3. ★★ **单侧检验会在混淆项存在时"通过"。** 激波偏置的方向检验通过了，因为一阶耗散
   和粘性位移同向。单侧判据不仅分不清"对的大偏差"和"错的大偏差"（上一轮翼尖那次），
   也分不清"对的原因"和"另一个同向的原因"。
4. ★★ **及早终止比跑完更省。** D10 六条腿在两小时处被终止；跑完只会得到六个作废解。
   判断依据是 deck 里的一行，代价是零计算。
5. ★ **把发现的缺陷在源头设成硬断言**，并逐一验证断言对"必须报错"和"必须放过"两组
   用例都正确 —— 只验证一半的断言等于没验证。

## 9. 第二个报告代码缺陷：CFL3D 的 SUMMARY 不是"跑完了"的证据

L2 死在 `NaN ... block 1 cycle 540`，而我的 runner 报 **`ok cl=+0.339608`**。两个独立
原因：它在 `cfl3d.out` 里 grep `NaN`（消息写在 `cfl3d.error`），并且把"存在 SUMMARY
块"当作成功 —— **CFL3D 在失败退出的路上也会写一个 SUMMARY**。数值算得没错，是判定
把一个发散状态发表了出去。

★★★ **写出正确的检测器之前错了三次，每一次都是靠"拿已知结果的算例校准"发现的**：

| 版本 | 判据 | 为什么错 | 怎么发现的 |
|---|---|---|---|
| 1 | `cfl3d.out` 里有 NaN | 消息不在那个文件 | L2 被报成 ok |
| 2 | 存在 SUMMARY 块 | 失败的运行也写 | 同上 |
| 3 | `cfl3d.error` 非空 | **成功的运行也写** | **第一次使用就把已知 good 的 L1 判成失败** |
| 4 | `cfl3d.error` 的**错误码** + IT 达到 `mseq*ncyc` | — | 对 6 个已知结果零不符 |

`mseq` 会让它提前一层"看起来完成了"。正常终止横幅**只**出现在 `cfl3d.error` 里 ——
`cfl3d.out` 和 stdout 都没有，这是第 3 版错误的直接来源。

⇒ `generate_m6_reference.py` 现在**拒绝发表未完成的档位**；`tests/F08` 用合成运行锁住

运行**确实**返回 0.33960762016 —— 陷阱必须是活的，否则锁只是表演。

死时 CFL 跨 **0.73–1.93（2.6 倍）**，⇒ **CFL 不是控制变量**；放慢升速只把死亡从 +39
推到 +75 步。

★★★ **过程教训（我犯的）**：在只有 control 和 early 死掉、cfl2 与 slowramp 还在跑的
时候，我把"两条慢升速的还活着"读成了信号，并据此提出"升速率是关键"。**它们不是幸存
者，只是死得晚。** 一个中间状态的"还没发生"不是"不会发生" —— 这与项目里
"`budget_limited` 不是失败"是同一条教训的反面：**"还没失败"也不是"收敛"**。

### 11.2 和一个能工作的二阶参照对比，而不是继续猜

2-D 数据集是**二阶且能工作**的。对比两边的数值卡：**完全相同**（IFDS 1 / RKAP0
0.3333 / IDIAG 1 / IFLIM 4）。所以不是格式参数的差别，问题在别处。

于是读限制器本体，`cfl3d/libs/xlim.F` 的结尾：

```fortran
c     cap density and pressure
c     - ensures that they stay positive
c     - limits their maxima to their stagnation values
      if (ichk.eq.2) call prolim (n,x1,x2,xc,leq)
      if (ichk.eq.3) call prolim2(n,x1,x2,xc,leq)
```

**CFL3D 自带一个作用在"重构出的密度与压力"上的正性限制器，由 `ICHK` 控制，而我们
所有 deck 的 `ICHK` 都是 0。** 二阶 MUSCL 在细网格强激波处正是会把密度重构成负值的
地方 —— 那就是 NaN。`ICHK` 的唯一其它消费者是 `bc2006.F`（BC 类型 2006），本算例
不用，所以打开它没有副作用。

★ 这同时解释了 2-D 为什么没事：**同样 `ICHK = 0`**，但 NACA0012 在 M0.8/α1.25 的
激波远比 M6 在 M0.8395/α3.06 加翼尖区温和。**同一个隐患，2-D 只是没有踩到。**

### 11.3 实测：L2，其余配方逐字相同

| 腿 | wall | 结果 | cl | cd |
|---|---|---|---|---|
| ICHK 0（对照）| 1414 s | **发散 @ icyc 540** | — | — |
| ICHK 2（prolim）| 2822 s | **ok 4500/4500** | +0.341771 | 0.013982 |
| ICHK 3（prolim2）| 2835 s | **ok 4500/4500** | +0.341767 | 0.013982 |

★★★ **两个限制器都work，而且彼此一致**：cl 差 4e-06（相对 1.2e-05），cd 六位完全
相同。**这正是"修复"与"调参"的分界** —— 两个独立实现给出同一个收敛答案，说明限制器
阻止的是不可接受状态，**而不是在塑造答案**。

★ 对照腿放在**同一批**里跑，所以比较的是当场复现的失败（icyc 540，与阶梯那次同一步），
不是记忆里的失败。

⇒ `ichk` 已作为参数暴露在 `write_inp`（此前硬编码 0），M6 阶梯用 `ICHK = 2`。
`tests/F08` 用**行为检查**锁住它：把字段改回硬编码 0，恰好 `ichk=2/3` 两例变红而
`ichk=0` 仍通过 —— 一个"被接受但没写进 deck"的参数，与 F06 那个字面量对字面量的判据
是同一种缺陷。


### 11.4 `ICHK` 的答案中性：实测到 2e-05 相对，**不是"完全相同"**

在 **两种设置都收敛** 的三个算例上做直接 A/B（L1 那一档 ICHK 0 本来就跑得通，所以
这个对照是可做的）：

| 算例 | 量 | ICHK 0 | ICHK 2 | 相对差 |
|---|---|---|---|---|
| Euler L1 | CL | +3.42948635740e-01 | +3.42950368860e-01 | 5.05e-06 |
| | CD | +1.42913221080e-02 | +1.42916054350e-02 | 1.98e-05 |
| RANS L1/sst | CL | +3.20917713850e-01 | +3.20918191410e-01 | 1.49e-06 |
| | CD | +2.09816709220e-02 | +2.09817810360e-02 | 5.25e-06 |
| RANS L1/sa | CL | +3.32725153730e-01 | +3.32724986820e-01 | 5.02e-07 |
| | CD | +2.21900794160e-02 | +2.21901748250e-02 | 4.30e-06 |

★★★ **更正我自己的一个过度陈述。** runner 打印到 6 位小数，RANS 两腿在那个精度下
逐位相同，我据此说"identical to every printed digit … 最强的中性结果"。**在全精度下
它们并不相同**（相对 5e-07…2e-05），而且残差历史文件**逐字节不同** —— 也就是说
**限制器确实在某些地方起作用了**，只是对积分力的影响极小。**"打印位数相同"不等于
"相同"**，这和本项目"不要要求浮点乘积逐位相等"是同一类分辨率错误。

正确的陈述是：**`ICHK` 对答案的影响在 5e-07…2e-05 相对量级**，而 Euler 阶梯在 cl 上的
档间差约 1e-02 相对 —— **限制器的影响比要测的信号小约 2000 倍**。这仍然支持"它阻止
不可接受状态、不塑造答案"的结论，但结论的强度要按这个数字说，不能按"完全相同"说。

★ 附带一条平凡但正确的恒等式：Euler 的 `CDv` 两边都精确为 0（无粘项不存在）。

⇒ 于是现在有**三条独立的中性证据**：ICHK 0 vs 2 在 Euler L1（5e-06）、RANS L1/sst
（1.5e-06）、RANS L1/sa（5e-07）；以及 prolim vs prolim2 在 L2（1.2e-05）。

### 12.3 ★★★ 激波位置对这个实验根本没有分辨力 —— 本轮最尖锐的一条

M6 实验的 Cp 采样间隔是 **0.040–0.050 c**，所以从它反推的激波位置，精度不可能
好于该间隔的一半。二阶实测（读最细档 L4）：

| y/b | Δx | Δx / 采样间隔 | 判定 |
|---|---|---|---|
| 0.20 | +0.0305 | 0.61 | 方向如预期 |
| 0.44 | +0.0212 | 0.42 | **UNRESOLVABLE** |
| 0.65 | +0.0145 | 0.29 | **UNRESOLVABLE** |
| 0.80 | +0.0067 | 0.14 | **UNRESOLVABLE** |
| 0.90 | +0.0124 | 0.31 | **UNRESOLVABLE** |
| 0.96 | −0.0068 | 0.17 | **UNRESOLVABLE** |
| 0.99 | — | — | 撤回（检测器前提）|

**七站里只有一站有分辨力**，而它与预期方向一致。⇒ **此前"激波在实验下游、6/6
站位方向如预期"的读数作废**：那是在一阶数据上测的，其位移（+0.025…+0.072 c，
最高达采样间隔的 1.4 倍）之所以超过参照物的分辨率，**只是因为解本身是错的。
修好格式反而把"信号"消掉了。**

★★★ 这是判据缺陷家族里一个值得单独命名的形态：**判据把一个量与一个"自身分辨率
比所有被报告差值都粗"的参照物相比。** 它和"两个数是不是同一个东西"是邻居，但问
的是另一件事：**参照物有没有能力分辨你要报告的差别。**

★★ 它同时也退掉了一个"anomaly"。η=0.96 上二阶激波落在实验**上游**（−0.0068 c），
按事先登记的单侧条款这本该判为"与粘性机理矛盾"。但它是实验采样间隔的 0.17 倍、
该站自身网格误差棒的 2.0 倍 —— **低于被比较对象的分辨率**，所以分辨率闸门在读符号
之前先触发。★ 检测器这次不背责任：η=0.96 的上游深度在四档上都健康（0.68–0.84）；
真正前提失效的是 η=0.99，而且它在 **L1 和 L4（最细档）都失效** —— 加密治不好。

★ **活下来的偏置**：合并 Cp RMS **0.087–0.135，均值 0.1065**，上表面是下表面的
**3–4 倍**。它比较的是**测点处的 Cp 值**、不反推位置，所以采样间隔动摇不了它。

### 12.4 吸力峰那条修正，本身又被修正了一次

一阶那轮记的是"峰值没有可预测符号，**因为网格截断主导**（`cp_min` 每站非渐近）"。
二阶下 `cp_min` **七站全部渐近**（误差棒 3.2e-05…1.7e-02），截断不再主导。
峰值**仍然没有可预测符号** —— 因为两个反向机制（粘性减弯 vs 有限网格低分辨）依旧
对立 —— 但**理由从"这个量还没收敛"换成了"两个竞争机制"**。理由错了而结论对，
和理由对而结论对，不是一回事。

### 12.5 一个我自己的报告缺陷（第三个）

`compare_m6_experiment.py` 的汇总行把**任何非 "as predicted" 的行都算成
