## 0. 一句话

`cfl3d.inp` 里 **`NITFO ≥ NCYC`**，于是 CFL3D 在最细网格上**整个求解过程都用一阶
空间精度**，而 deck 里明明写着 `RKAP0 = 0.3333`（κ=1/3 MUSCL）。M6 的 Euler 阶梯
（`nitfo 1000 / ncyc 1000`）和 M6 的 RANS 阶梯（`nitfo 1000 / ncyc 800`）**两条都
中了**；2-D 的四个数据集**没有中**（`NITFO` 0 / 500 / 1500 对 `NCYC` 1000 / 2000 /
2000，都会切换）。

---

## 1. 机理（读源码，非推测）

`cfl3d/libs/resid.F:141`

```fortran
if (icyc.ge.nitfo+1 .and. level.ge.lglobal) then
   rkap(1:3) = rkap0(1:3)      ! 请求的精度（κ=1/3）
else if (level.ge.lglobal) then
   rkap(1:3) = -3.             ! ★ 一阶
else
   rkap(1:3) = rkap0(1:3)      ! 多重网格的粗层
end if
```

`rkap = -3.` 是 CFL3D 的一阶标志。关键在 `icyc` 的作用域 ——
`cfl3d/dist/mgblk.F:416`：

```fortran
levt  = levelt(iseq)
nitfo = nitfo1(iseq)          ! ← 每个 mesh-sequence 层各自的 nitfo
ncyc  = ncyc1 (iseq)
...
do 7000 icyc=1,ncyc           ! ← icyc 在每层都从 1 重新开始
```

⇒ `icyc` **不是累计的**，它和本层自己的 `nitfo` 比。`ncyc = nitfo = 1000` 时
`icyc >= 1001` 永不成立，而 `level >= lglobal` 在最细全局网格上恒成立 ⇒ **最细网格
1000 步全部一阶**。粗层用的是 `rkap0`，但决定收敛解的是最细层的残差，所以那不救。

★ 日志末尾显示 `it = 3000`，是三层各 1000 步的**累计打印计数**，不是 `icyc`。我先前
把它当成了 `icyc` 的证据 —— 这正是这个缺陷能藏住的原因之一。

## 2. 为什么读 deck 抓不到

`.inp` 里两条阶梯都老老实实写着

```
   IFDS(I)   IFDS(J)   IFDS(K)  RKAP0(I)  RKAP0(J)  RKAP0(K)
         1         1         1    0.3333    0.3333    0.3333
```

**一个"请求的"参数不是"生效的"参数。** 这和本项目已记录的 "signature is not the
contract"、"a knob's name is not its scope" 是同一族。能抓住它的检查只有两种：

1. 读源码确认门槛（本轮做的）；
2. **行为检查** —— `nitfo < ncyc` 时残差历史必须在 `icyc = nitfo+1` 处出现可见断点
   （精度切换会激起残差跳跃）。若没有断点，切换就没发生。

⇒ 已在 `wing3d_otip.py::write_inp` 和 `cfl3d_runner.py` 的配方表加了 `nitfo < ncyc`
的硬断言（import 时即校验，四个用例逐一验证过：1000/1000 和 1000/800 必须 raise，
1000/2000 和 0/1000 必须通过）。

## 3. 是怎么被发现的 —— 值得记下来的路径

**不是**看着数字不对发现的，而是去给一个判据找参照时发现的。

用户批准加第四档后，第一件事是问"这条阶梯上，一个 p 阶收敛的量*应该*给出多大的
比值"。算下来：以 `h ~ N^(-1/3)`（总点数）为网格尺度，这条阶梯近乎均匀
（r = 1.376 / 1.340，比值之比 1.027），于是

| p | 预期比值 |
|---|---|
| 2.00 | 0.496 |
| 1.00 | 0.675 |
| 0.50 | 0.787 |
| 0.25 | 0.849 |

而实测：cd 比值 0.744 ⇒ **隐含阶数 p = 0.68**。一个请求了 κ=1/3 的格式，在光滑区
不该只有 0.68 阶。**是这个不一致把注意力引向"格式到底是几阶"**，而不是任何一个
"看起来不对"的数。

★★ 顺带暴露了我自己的判据缺陷：**"ratio < 1" 从来没有被标定过**。1.0 不是收敛量
给出的值，只是"差不再缩小"的分界。这条判据放过了 0.2 阶的量。已改为在表里同时报
**隐含阶数**，读者要把误差棒减半时能算出代价（p = 0.68 时需要点数增大 2.8 倍，
不是 1.4 倍）。这是相三那张"四个判据缺陷"表的"阈值无标定"形态。

3. **吸力峰偏浅**我归因为"有限网格总会低分辨前缘峰"。方向对，但一阶耗散是更强的

4. **隐含阶数 cd 0.68 / 激波 4.90→0.43** 是**一阶格式的**阶数；0.7–1.0 对捕获激波的

## 5. 替代配方 —— 为什么不能简单把 nitfo 设 0

`nitfo` 的长一阶启动在这个算例上是**承重的**：已提交的收敛标定表里 CFL 1.0 和 0.8
都发散，只有 `CFL 0.2 / NITFO 1000` 这条到了 |R| 8e-11。所以修法是 **`ncyc > nitfo`**，
而"需要多长的一阶启动"是个待测量的问题，不是可以猜的。

L1 上三条腿（其余全同）：

| 腿 | nitfo / ncyc | 目的 |
|---|---|---|
| control | 1000 / 1000 | 复现已提交档位（应与 committed L1 一致） |
| long | 1000 / 2000 | 保住已验证的启动，之后 1000 步二阶 |
| short | 500 / 1500 | 启动减半，同样的二阶预算 |

`control` 这条腿同时是**仪器校验**：它必须复现 committed L1 的 cl 0.325440 /
cd 0.033666（原始 SREF=1 值）。如果不复现，问题就不只是 nitfo。

### 5.1 实测结果（2026-09-03，L1，4 线程/腿，load ~2）

| 腿 | nitfo/ncyc | wall | cl | cd | \|R\| | drop |
|---|---|---|---|---|---|---|
| control | 1000/1000 | 506.1 s | **+0.325440** | **0.033666** | 1.636e-10 | 3.87 |
| long | 1000/2000 | 1032.5 s | +0.342948 | 0.014291 | 2.163e-08 | 2.27 |
| short | 500/1500 | 821.1 s | +0.342949 | 0.014291 | 2.172e-08 | 2.27 |

三条结论，都是硬的：

1. ★★ **仪器校验通过** —— `control` 把 committed L1 复现到每一位（cl 0.325440 /
   cd 0.033666 / |R| 1.636e-10 / drop 3.87），所以已提交的那一档**确实就是**这个
   一阶解，缺陷定位无歧义。
2. ★★★ **二阶把答案挪动了很多**：cl **+5.38 %**，cd **−57.6 %**。cd 掉一半以上是
   一阶数值耗散的签名 —— 一阶格式引入伪熵、伪阻力。⇒ 已发表的 D07 阻力**高了一倍多**。
3. ★★ **一阶启动的长度不影响答案**：`long` 与 `short` 的 cl 差 1e-6 相对、cd 完全
   相同、|R| 差 0.4 %。⇒ 500 步启动够用，`short` 便宜 20 %。**配方 = nitfo 500 /
   ncyc 1500，由测量定，不是猜的。**

二阶腿的残差落在 |R| 2.2e-08 / 2.27 decades，高于一阶腿的 1.6e-10 / 3.87 —— 符合预期
（更高阶的残差更难压，激波限制器造成平台），且仍在 ≥ 2 decades 的可用范围；四档
阶梯的残差口径会逐档记录。

### 5.2 行为检查：精度切换确实发生了（独立于源码阅读）

`order_switch_check.py`：切换空间算子会扰动解，所以残差历史必须在
`icyc = nitfo+1` 处出现可见断点。实测（相邻步 |Δlog10 R| 对中位数的倍数）：

| 腿 | 断点位置 | 幅度 | 判定 |
|---|---|---|---|
| long | icyc **1001** = nitfo+1 | **1049×** 中位数 | 切换发生 ✓ |
| short | icyc **501** = nitfo+1 | **602×** 中位数 | 切换发生 ✓ |
| control | 最大跳变在 icyc 1000 = **最后一步** | 828× | 无切换（是末尾多余行的伪迹）✓ |

★★★ **这个检查自己先出过两次错，而且第二次是"自信地报了错误结论"**，值得记下：

1. 第一版把第 1 列当成迭代数 —— 实际列布局是 `LV BLK IT res Tres Cl Cd Cdp Cdf`，
   第 1 列是 **mesh-sequence 层号**。于是 `it.max()` = 3，窗口选中了全部行，
   它报出 **"switch did NOT fire"** —— 而同一批腿的答案已经动了 5.4 % / 57.6 %。
   **一个坏了的仪器给出自信的判定，比直接报错更糟。** 我没有采信它，因为它和一个
   强得多的测量矛盾 —— 这正是"别把工具的结果照单全收"该起作用的地方。
2. 第二版修对了列，但假设 `IT` 每层重置。实际 `IT` 是**累计**的，而 Fortran 的
   `icyc` 每层重置（mgblk.F:416）—— 两个计数器同名不同义。修正是
   `icyc = IT − (nlv−1)·ncyc`。**发现它的线索是：最大跳变落在 3501 和 5001，
   恰好等于"第三层起点 + nitfo+1"** —— 数据自己指出了偏移量。

★ 附带确认了用户提示的那个遗留问题：`control` 的最细层有 **1012** 行而 `ncyc = 1000`，
多出的 12 行就是末尾多余输出；`control` 的最大跳变正落在最后一步上。**这也是不能靠
行位置取力系数的又一个证据**（力系数已改从 `cfl3d.out` 的 SUMMARY 取）。

## 7. 教训（按可复用性排序）

1. ★★★ **一个"请求的"参数不是"生效的"参数。** 要么读源码确认门槛，要么写一个
   **行为检查**去看它是否真的生效。本项目已经栽在同一族上多次：签名不是契约、
   旋钮的名字不是它的作用域、F06 的 "reads the CSV" 其实是字面量对字面量。
2. ★★★ **判据必须先标定，再使用。** "ratio < 1" 里的 1.0 是个圆整的数，不是任何
   收敛量给出的值。要问的是"这条阶梯上 p 阶应该给多少"。**去给判据找参照的那一步，
   本身就是发现缺陷的手段** —— 本轮就是这么发现的。
3. ★★ **单侧检验会在混淆项存在时"通过"。** 激波偏置的方向检验通过了，因为一阶耗散
   和粘性位移同向。单侧判据不仅分不清"对的大偏差"和"错的大偏差"（上一轮翼尖那次），
   也分不清"对的原因"和"另一个同向的原因"。
4. ★★ **及早终止比跑完更省。** D10 六条腿在两小时处被终止；跑完只会得到六个作废解。
   判断依据是 deck 里的一行，代价是零计算。
5. ★ **把发现的缺陷在源头设成硬断言**，并逐一验证断言对"必须报错"和"必须放过"两组
   用例都正确 —— 只验证一半的断言等于没验证。
